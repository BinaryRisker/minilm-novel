# 2026-09-13 · 公版中文小说语料采集

## 问题

原有语料只有 3 篇自写短文（科幻 2668 字 / 武侠 2125 字 / 都市 2567 字，合计 7360 字），
上一轮数据量扫描的结论是「12 组配置全部未能超过 trigram」，且曲线尚未收敛。
本轮要回答的是：**把语料从「千字级」扩到「百万字级」后，模型还缺什么？**

## 假设

如果瓶颈确实是数据量，那么在不改模型配置的前提下把训练语料放大 3 个数量级，
模型 Top-1 应显著上升，且模型相对 trigram 的差距应收窄甚至反超。

## 唯一变量

训练语料。模型配置（ctx=32 d=40 layers=2 heads=4 ffMul=4）、优化器（Adam lr=0.004，
warmup+cosine）、步数 400、seed 1234、留出集协议（全文最后 10%）全部不变。

## 踩过的坑（都可复现）

1. **Gutenberg 按约 37 字硬换行**，直接入库会把一个自然段切成多行。
   按其行宽特征（行宽 ≥ 28 且行尾非句末标点）重排回自然段。
2. **维基文库正文靠转写**，`prop=extracts&explaintext` 只能拿到导语（月界旅行 17 页只得 292 字）。
   必须用 `action=parse&prop=text` 取渲染后 HTML 再剥标签。
3. **维基模板噪声**：繁简转换说明、版权声明、每页重复的章节导航表。
   关键词删行不彻底（同一说明有繁简多种写法），最终用「整段命中 ≥2 个噪声关键词」+「长度 ≤16
   且重复 ≥3 次的纯汉字短行」两条规则清掉。
4. **HTMLParser 子树跳过会失步**：MediaWiki 存在不闭合标签，`skip` 深度计数一旦失衡会整页丢内容
   （实测把 `猫城记` 整本吃掉）。改为「正则剥标签 + 行/段级过滤」更稳。
5. **长尾生僻字**：2 兆字语料带来 6400+ 独立字符，其中不少是扩展 B~G 区的 1 次出现字。
   用 `build_vocab(min_freq=3)` 把它们映射到 UNK，词表降到约 4479–5245，
   嵌入表参数从 25.6 万降到约 18–21 万。
6. **基线评测步长 bug（影响上一轮结论）**：`py/baselines.py` 的 `for_each_position`
   步长写成了 1（应为 `ctx`），与 `minilm_torch.holdout_eval` 的「每 32 字一窗」不一致，
   导致基线被评测 **32 倍**的位置；叠加 `NGram.dist` 用 Python 循环遍历整个词表（O(V)），
   单次基线评测耗时 13 分钟。修好后基线耗时降到 7 秒量级，两者也在同一批次评测位上比较。
   → **上一轮「全部未超过 trigram」的数字需要用新协议复核**（见 `2026-09-13-sweep-data-scale.md`）。

## 结论边界

- 语料全部为公版文本，**风格集中在明清白话/文言**，与现代网络小说有明显语体差距；
  用它可以研究「小模型能多快学到字级分布」，但不能宣称模型会写现代小说。
- `scifi` 桶只有 13.2 万字（维基文库 4 部），体量远小于其他桶；跨桶比较时须注意这一点。
- 单桶上限 200 万字是**均分截断**：长作品被截断，不是全文入库。
- 入库的是繁转简后的文本，原始繁体版本只保留在抓取缓存中（未入库）。

## 复现

```bash
python py/data/fetch_corpus.py --list-sources                 # 看源清单，不下载
python py/data/fetch_corpus.py --max-chars 2000000            # 全量抓取 + 清洗 + 分桶
python py/data/prepare.py --split                             # 逐作品 manifest + split 审计
python py/sweep_data_scale.py --sizes 2000,10000,50000,200000,1000000,all --steps 400 --min_freq 3
```

产物：

- `py/data/corpus.json` — 训练直接可用的分桶语料
- `data/sources.json` — 90 部作品的来源 / 许可 / 字数 / 哈希 / 链接
- `data/processed/<bucket>/*.txt` — 逐作品清洗后正文（本地抽查用，不入库）
- `data/manifest.jsonl` + `data/split_audit.json` — 逐作品清单与 split 审计
