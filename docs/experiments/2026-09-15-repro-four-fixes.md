## 0. 四个缺陷与判据（一句话版）

| 区域 | 缺陷（修复前实测） | 判据 | 结果 |
|---|---|---|---|
| seed | `train.py` 在 `torch.manual_seed` **之前**构造模型 → 初始权重不受控 | 同 seed 两次逐位一致 | 修复后 `max|Δ|=0`；旧顺序 `init max|Δ|=0.122`、`final=0.218`（与换 seed 的 0.218 同量级） |
| 断点续训 | resume 只打印 `no retraining`；checkpoint 只有 `model/itos/meta` | 直训 N 步 ≡ 训 N/2 + 续训到 N（逐位） | 修复后 `max|Δ|=0.000e+00`、探测 loss 完全相同；丢 RNG/丢优化器/全丢分别漂移 9.2e-2 / 8.6e-2 / 1.15e-1 |
| 数据隔离 | 按作品切分后 gudian 留出集仍有 12%~14.7% 的 40 字片段能在 train 里逐字找到（异名同书/选本） | 片段级精确查找命中 0 | v1 审计 val 18/150、test 22/150 → v2 全部 0/150 |
| 故事评测 | 提示词文件不存在；采样无种子；指标算在 `prompt+生成` 上；无基线 | 出题来自留出集 + 生成可复现 + 指标不送分 | 事件完成度旧口径 100% → 新口径 **0%**；同 seed 生成逐字相同 |

## 1. 种子

- 新增 `py/repro.py`：`set_global_seed`（random/numpy/torch）+ `rng_state/set_rng_state`（两套 RNG 打包）。
- **调用顺序写死**：先设种子，再建词表与模型。`py/train.py` 已按此顺序重写。
- 关键数字：旧顺序下「同 seed 跑两次」的末步差异 2.181e-01，与「换成 seed=4321」的 2.178e-01 同量级 → 修复前的 seed 等于装饰品。

## 2. 断点续训

- checkpoint v2：`version/model/opt/itos/meta/step/rng`；旧格式仍可读入但告警。
- 新增 `--stop_at`：lr 调度按**计划总步数**归一，否则「先训一半」的 warmup/余弦形状与续训不一致，等价性无法成立。
- 归因表（基准 A 直训 160 步、探测 loss 5.2746）：

| 变体 | 丢失 | 末步 max&#124;Δ&#124; | 探测 loss | Δloss |
|---|---|---|---|---|
| B 完整状态 | — | **0.000e+00** | 5.2746 | +0.0000 |
| C1 | RNG | 9.202e-02 | 5.2599 | −0.0147 |
| C2 | 优化器 | 8.589e-02 | 5.3003 | +0.0257 |
| C3（= 旧格式） | 全部 | 1.154e-01 | 5.2903 | +0.0156 |

- **要点：C1 的 loss 反而更低** → 「续训后 loss 更低」不能作为续训正确的证据，逐位一致才是。
- 踩坑（三个独立原因，全部已修）：验证脚本覆盖了中途 checkpoint；采样用独立 `Random` 实例而 `rng_state()` 存全局流（两条流不同）；续训没沿用 `--chars`（数据都不同）。

## 3. 数据隔离

- `py/audit_splits.py`：五组检查（清单级 / 片段级精确查找 / 词表 OOV / 训练集内重复 / 旧口径对照），违规时非零退出。
- 泄漏形态（gudian，全部是「同内容不同身份」）：《新齐谐》↔《子不语》锚点 0.572（精确 0.421）、《三国演义》↔《三国志演义》0.552（0.369）、《今古奇观》把三言二拍串成 **7 部同源簇**（《警世通言》0.135/0.058、《醒世恒言》0.094/0.041、《西湖二集》0.067/0.044、《喻世明言》0.067/0.022）。
- `py/dedup_works.py`：winnowing 锚点（内容决定、对齐无关、crc32 可跨进程复现）+ 并查集合并 → `data/manifest_v2.jsonl`（**不改原文件**，旧实验可复现）+ 配套 `data/split_report_v2.json`。gudian 移动 4 部 → 44/5/6 变 48/4/3。
- 修复效果：审计 v2 全部 0/150 通过。
- **失败样本（诚实记录）**：`py/leak_probe.py` 同一模型跨测试集逐作品对比，污染组比干净组 Top-1 只高 **+0.29/+0.52/+0.18（均值 +0.33±0.14）**，NLL −0.082±0.005。作品间差异是 8.16%~12.39% → **修了泄漏，指标几乎没变**，但这不构成「不用修」的理由。
- 方法学踩坑：两边各自 stride 抽样求集合交集会把重合度稀释 1/stride（38% → 3.8%，漏检）；改用「对另一部全文精确查找」太慢（1.25s/对）→ 最终 winnowing（22s 跑完 3 桶）。
- 旧口径对照：gudian 1 部（剪灯新话）跨两段；test 段只含 4 部最短作品；拼接丢弃全池 81.9% 正文（wuxia 63.7%、urban 52.8%）。

## 4. 故事评测

- `py/eval_story.py` 重写：出题只从留出作品（记录 story_id/title/split/offset）；`--seed` 驱动采样；指标只在生成段上算（旧口径另存 `model_old_protocol` 作对照）；`--baseline trigram` 同解码参数同种子。
- 修掉的实现 bug：`generate()` 返回的文本本就含提示词，调用方又拼一次 → `generated_chars` 虚高（160 vs 120）。
- 旧口径送分幅度：事件完成度 **100% → 0%**、事实关键词 83% → 50%。
- 最小闭环（story 桶 6 万字 / 600 步 / 中途 300 步存盘再续训，全程 47s）：val top1 21.88→21.69、nll 4.485→4.310；test top1 29.83%、nll 3.998。
- **失败样本**：模型生成最长连续重复 **6.67 字**（trigram 基线 2.00）、dup4 0.056（基线 0.011）、novelty4 0.657（基线 0.209 —— 模型「新颖」是因为在瞎编）。报告副本入 `dev/verify/loop_report_0915_003515.md`（+ `loop_summary_0915_003515.json`、`loop_commands_0915_003515.txt`）；全量样本与 checkpoint 在 `dev/loop/closed_0915_003515/`（本地，可由 `py/closed_loop.py` 重建）。
