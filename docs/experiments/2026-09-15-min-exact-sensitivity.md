# `--min-exact` 敏感性扫描：把拍的阈值换成量出来的 ∈ (0, 0.0159]

> 对应脚本：`py/audit_neardup.py`（守卫 2 的默认值由 0.02 改为 **0.005**）
> 上游索引：`docs/experiments/2026-09-15-neardup-all-buckets.md` §5、§10 第 2 条
> 内容稿：`docs/content/实践篇36_数据涨了六倍我的去重脚本就再也跑不完了.md`

## 1 要解决的问题

上一轮给锚点法加了守卫 2（`--min-exact`，精确复核门槛），默认 **0.02**，理由是「story 桶 10 个
『簇』的精确复核全为 0.0，照单全收会凭空造出跨 split 泄漏」。

但它的代价是：gudian/test 残留 **2.00%** 泄漏（门禁**失败**），诊断指向
《今古奇观》(train) ↔《二刻拍案惊奇》(test) 这对**真选本**——锚点 **0.0519 过了 0.05**，
精确复核 **0.0159** 差一点没过 0.02。

上一轮把默认值留成 0.02，理由是「0.005~0.019 区间只有两个数据点」。这一轮把它补成完整扫描。

## 2 方法：一次 dump，离线扫全部阈值

`--dump-pairs` 把**过锚点阈值之后、精确复核之前**的全部候选对逐条写出（含 `exact_max`），
所以**不需要**为每个阈值重跑检测器：一次 `--min-exact 0` 就拿到全量边集，阈值扫描在离线重算并查集。

```bash
# 只用小桶（localugc 走行级倒排，不受 --min-exact 影响，单独跑等价且省内存）
python py/audit_neardup.py --buckets gudian,wuxia,urban,xiandai,scifi,story --algo anchors \
    --min-exact 0 --manifest dev/verify/manifest_small.jsonl --report data/split_report.json \
    --dump-pairs D:/work/_pairs.jsonl --out D:/work/_scan0.json     # ≈50s
```

## 3 实测：六个小桶的候选对**全量只有 24 对**

| 桶 | 候选对 | `exact_max` |
|---|---:|---|
| gudian | 8 | 0.4214 / 0.3693 / 0.0584 / 0.0442 / 0.0409 / 0.0254 / 0.0220 / **0.0159** |
| story | 16 | **0.0000 × 16** |
| wuxia / urban / xiandai / scifi | 0 | — |

升序全貌（24 个数）：

```
0.0000 ×16   →   0.0159  0.0220  0.0254  0.0409  0.0442  0.0584  0.3693  0.4214
└─ 噪声 ─┘      └────────────── 真同源 ──────────────┘
```

**分布是双峰的，中间是一条空档。** 噪声不是「偏小」，是**恰好为 0**——story 桶的 16 对
锚点值 0.0500~0.0909（**全部过了锚点阈值 0.05**，说明锚点守卫单独不够用），
但 2,000 个 40 字探针**一个都命不中**。真同源里最小的 0.0159 已相当于 ~32 个探针命中
（≥32 处 40 字连续逐字重合）。

## 4 扫描结果：0.02 落在真同源**内部**

| `--min-exact` | 保留对 | 跨split对 | 跨split簇 | gudian簇 | story簇 | 成员变化 |
|---|---:|---:|---:|---:|---:|---|
| **0.0** | 24 | 9 | **7** | 3 | 4 | story 凭空多 4 个跨 split 簇 |
| 0.0005 | 8 | 4 | 3 | 3 | 0 | — |
| **0.005** | 8 | 4 | 3 | 3 | 0 | **含 `gudian_012`** ✓ |
| 0.01 / 0.012 / 0.015 / **0.0159** | 8 | 4 | 3 | 3 | 0 | 同上 ✓ |
| 0.016 / 0.018 / **0.02（旧默认）** | 7 | 3 | 3 | 3 | 0 | **丢掉 `gudian_012`** ✗ |
| 0.025 | 6 | 3 | 3 | 3 | 0 | 再丢 `gudian_017` |
| 0.03 / 0.05 | 5 / 3 | 3 | 3 | 3 | 0 | 再丢 `gudian_009` / `gudian_014` |

### ★ 这次扫描最该记住的一点：**聚合指标对这次回退是盲的**

`跨 split 簇数` 在 `0.0` 之外**全程恒等于 3**——0.005 是 3，0.02 是 3，连 0.05 也是 3。
如果只看「跨 split 簇 = 3，和上一轮一致，没退化」，就会**完全看不到** `gudian_012`
（《二刻拍案惊奇》）已被踢出簇、留在 test 里继续泄漏。

差别只在**簇的成员表**：

```
min-exact ≤ 0.0159:  {001 今古奇观, 009, 012 二刻拍案惊奇, 014, 015, 017, 018}   ← 012 在簇里 → 移入 train
min-exact ≥ 0.016 :  {001 今古奇观, 009,      014, 015, 017, 018}                ← 012 掉出去 → 留在 test
```

## 6 新默认值 0.005 的依据

1. **必须 > 0**：噪声floor 是**恰好 0.0000**（16/16），不是「偏小」。
2. **必须 ≤ 0.0159**：这是真同源里的最小值，跨过去就切掉真边（0.02 犯的正是这个错）。
3. 取 **0.005** 而不是贴着边界，是为了在两侧都留余量：
   - 可解释：0.005 × `--probe 2000` = **至少 10 个探针命中 ≈ 10 处 ≥40 字连续逐字重合**。
     单次巧合命中是 1/2000 = 0.0005，0.005 要求 **10 倍**于单点巧合。
   - 距最小真值有 **3.2×** 余量，距噪声 floor 有整整一个量级。

> 一句话：**旧默认 0.02 的事实描述是对的（「0.0 与 0.0159 之间」），只是把值放到了 0.0159 的另一侧。**

## 7 本轮**没做**的（诚实标注）

- **完整清单还没重新生成。** 本轮的产物只覆盖 6 个小桶（1,144 部）；`localugc`
  （**224,612 部 / 5.3 GB 正文**）走行级倒排，`--min-exact` 对它无影响，但它**必须重跑**
  才能把新旧语料对齐。
- **重跑现在被内存挡住**：本机 16 GB RAM 只剩 **1.6 GB 可用**，而 localugc 正文
  从 2.19 亿字涨到 **18.9 亿字**（约 8.6×），行级倒排的单位数从 338 万涨到约 2,900 万量级，
  估算常驻 4~8 GB。**且同一时刻并发工作线正在跑重活**（多个 python 进程 CPU 2,600s/6,300s），
  硬跑有把对方作业一起 OOM 掉的风险。→ 等机器空出来再跑。
- **`data/manifest_v3.jsonl` 现在是过期快照**：它建在 192,823 部语料上，而当前
  `data/manifest.jsonl` 是 **225,756 部**（实测；并发线的 LOG 写 226,725，**差 969 部**，
  疑似清单仍在中途重建）。指纹不同 → `resolve_current()` 的新鲜度校验会**拒绝**它，
  每次运行都会打一行 `[!] …不是同一批作品（过期快照）…` 告警（**实测已复现**）。
  `py/splits.py` 的 `DEDUP_CANDIDATES` 需要把新一代加进去；建议顺手改成
  **按 `data/manifest_v*.jsonl` 通配、版本号降序**，免得每出一代都要手改这个列表。
- 阈值 0.05（锚点）/ 200 字 / df 200 / `--min-shared 5` 仍是拍定的，本轮**只扫了 `--min-exact`**。
