# 结构消融：上下文长度 × 因果掩码

> 日期：2026-09-14。实验文件：`py/ablation_ctx.py`。
> 原始数据：`py/runs/abl_ctx_scifi_t20000.json`、`py/runs/abl_mask_scifi_t20000.json`、`py/runs/abl_ctx_wuxia_t20000.json`。

## 1. 问题

两个很便宜但一直没跑过的问题：

1. 把上下文从 8 拉到 64，模型在同一批评测位置上的成绩会变好吗？
2. 如果把因果掩码拿掉（让位置 i 能看到位置 j>i 的 token），会发生什么？

## 2. 一个不能省略的设计选择

第 1 题不能直接用 `py/sweep_worksplit.py` 的评测协议来答——它的窗口是「每 ctx 步一窗、窗内 history 长度 1..ctx」，**不同 ctx 评的是不同的 history 长度分布**。跨 ctx 比 Top-1 会被一个混淆遮住：ctx=8 永远不评 history 长度 >8 的位置，ctx=64 会。所以本次评测统一用：

> **固定一组位置 P**（要求 P 之前至少有 64 个字），每个模型都看「它能容纳的最后 ctx 个字」，预测「位置之后的下一个字」。所有 ctx 档在同一批位置上比。

这意味着：模型能用的最多信息是它的 ctx；位置集合对所有档位一致。

## 3. 唯一变量

| 项目 | 值 | 是否固定 |
|---|---|---|
| 桶 | scifi / wuxia | 是（分别跑） |
| 训练池前 20,000 字 | scifi/wuxia 各 | 是 |
| 留出切片 | 20,000 字（来自该桶留出作品轮取前缀） | 是 |
| 词表 | 在桶内全部训练作品上建，`min_freq=3` | 是 |
| 评测位置 | ≥ HIST_MIN(64) 等距抽样，封顶 8,000 个 | 是 |
| 步数公式 | `max(200, round(3 × 20000 / (32 × ctx)))` | 是 |
| 优化器 | Adam lr=0.004 + warmup(15%)/cosine + clip 1.0 | 是 |
| 随机种子 | 1234 / 42 / 2024（3 个） | 是 |
| **ctx** | **8 / 16 / 32 / 64** | **唯一变量（ctx 模式）** |
| **因果掩码** | **causal=True / causal=False** | **唯一变量（mask 模式，ctx 固定 32）** |

## 4. 配置与命令

```bash
python py/ablation_ctx.py --mode ctx  --bucket scifi --size 20000 \
    --ctxs 8,16,32,64 --seeds 1234,42,2024 --eval_cap 8000 --stride 3
python py/ablation_ctx.py --mode mask --bucket scifi --size 20000 \
    --seeds 1234,42,2024 --eval_cap 8000 --stride 3
python py/ablation_ctx.py --mode ctx  --bucket wuxia --size 20000 \
    --ctxs 8,16,32,64 --seeds 1234,42,2024 --eval_cap 8000 --stride 3
```

## 6. 关键发现

1. **scifi 上：上下文从 8 拉到 64，留出 Top-1 几乎不动（6.12→6.26%），NLL 略有改进（−0.06 nat）。** 全部 4 档都在种子 σ 以内。看 32 → 64 那一格：Top-1 +0.24pt，但 σ 是 0.25~0.41，**结论是「看不到收益」。**

2. **wuxia 上：上下文对 Top-1 有可见影响，但形状不是单调。** ctx=8→32 涨了 +0.79pt（σ 0.06~0.88），是真实差距；ctx=32→64 又回落到 +11.28%。曲线像「一个折点」：长上下文在长程依赖更强的文本上有点用，但**不是越长越好**。

3. **两个桶的 Top-1 都还输给 trigram，NLL 都赢 trigram。** 与 Day-2 的结论一致（`scifi` 1M 字档也未在 Top-1 上赢；NLL 全胜）。这意味着 ctx 不是这个项目的瓶颈。

4. **拿掉因果掩码，Top-1 反而掉 0.38pt、NLL 不变好（±0.006）。** 这是反直觉的——拿掉掩码、模型能看见「目标 token 后面的字符」的能力，**并没有带来收益**。原因有两个，并且这两个原因很值得讲清楚：

   - 在 `make_batch` 里，`tokens[i]=ids[s+i]`，`targets[i]=ids[s+i+1]`。**目标 token 在输入窗口里确实存在**（作为下一个位置的内容）——也就是说，无掩码模型**真的可以学到「把窗口里靠后位置的内容拷到当前位置」**。
   - 但留出集的评测用的是「用 `ids[p-ctx:p]` 预测 `ids[p]`」——**目标 token 不在窗口里**，这招抄不到。
   
   所以无掩码在训练阶段是有「作弊通道」的，但本实验的留出协议**专门设计成不暴露这个通道**，因此模型作弊得到的好处出不了训练集。**这也是为什么本项目的评测在加了掩码以后才是安全的：协议之所以公平，恰恰是因为因果掩码。**

5. **训练 loss：causal vs no_mask 差 0.027**（6.019 vs 5.992）。这个差异远小于「应该出现的崩溃」。原因是 20,000 字训练 + 200 步（≈3 epoch）的预算太短，模型还没来得及把「抄窗口内后位」这个捷径完全学会。如果预算翻 10 倍，理论上 no_mask 的训练 loss 应该会显著低于 causal。这条留作后续验证。

## 7. 失败样本 / 异常

- scifi ctx=16 的 Top-1 std 偏大（±0.50）：seed=1234 时掉到 5.73%，其它两个 seed 是 6.13% / 6.18%。可能是 200 步的优化轨迹里踩到了某个局部；仍在均值范围内。
- wuxia 的 ctx=32 与 ctx=64 几乎贴齐（Top-1 差 0.33pt，σ 0.06~0.10）。不是单调关系。

## 8. 结论与边界

**结论**：
> 在 6.6 万~7.3 万参数、固定训练预算（≈3 epoch × 32 batch × 20k 字）的范围内，把上下文从 8 拉到 64 在 scifi 上**几乎无收益**，在 wuxia 上**有可见但非单调的收益**。拿掉因果掩码，模型在固定位置评测下也不变好——证明本项目的评测协议是「依赖掩码才公平」的一类。

**边界**：
> - 只在 20,000 字训练、3 epoch 的预算下做；数据更多 / 步数更长时 ctx 的曲线可能更陡；
> - 只跑了 scifi（V=3741）和 wuxia（V=5,182）；`story` 短故事的句式模板化更强，Top-1 差距最大（Day-2），它的 ctx 曲线可能更平；
> - 因果掩码在更长训练下的崩溃幅度，未在本轮测；
> - 固定位置评测是「牺牲一点效率换可对比性」，真实应用里窗口会滑动，单 token 的边际可能不同。

**下一步**：
> 把预算拉到 10 万字 + 5 epoch，看 ctx 的差距是否随训练量扩大（特别是 no_mask 的训练 loss 是否会出现显著塌缩）；同样在 `story` 上做一遍。
