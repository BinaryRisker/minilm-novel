## 3. 必须先解决的问题

### A1 · P0：默认小说评测无法运行

`eval/prompts.jsonl:17` 与 `:29` 的 facts 对象存在没有键值配对的字符串。`py/eval_story.py:43` 直接 json.loads，遇到第 17 行即终止。现有单元测试没有覆盖该文件。

修复格式并加入 schema 检查；人物事实、场景任务、目标长度、唯一 prompt_id 均检查。非法记录必须给出行号，不能静默跳过后宣称完成 30 场景评测。本轮仅为诊断统计了 28 条合法记录，不是一次完整评测。

### A2 · P0：生成和事实指标会奖励提示词自身

`py/eval_story.py:87` 返回 prompt token 加续写；`:155` 又拼接原 prompt；`:160` 把两者混成 generated_chars。即使 max_new=0，也返回“小明推开了门。”。在 28 条可解析场景中，完全不生成，只检查提示词，就能命中 **48/59** 个“事实”名字和 **16/84** 个事件关键词。

`:94` 忽略事实描述，只判断 name in text。“苏念穿着红色外套”会通过“苏念穿蓝色外套”的检查。这个字段最多叫 name_mention，不能叫人物一致性。事件的短关键词命中也不是事件完成。

需要拆分 raw_prompt、effective_prompt、continuation；正文指标只统计 continuation。人物事实采用结构化断言，区分符合、矛盾、未提及；关键事件由完整事件语义与顺序判断，并保留人工判读。新增训练文本匹配检查，当前 Python 脚本未实现注释宣称的复制统计。

### A3 · P0：训练入口不保证同种子复现，也不支持真正续训

`py/train.py:120` 先构造 MiniLM，`:166` 后 manual_seed。两次独立 CLI 运行相同 seed、相同 256 字、相同配置、训练 1 步，权重不同；本轮最大差异约 0.11957。注意：`sweep_worksplit.train_curve` 在构造模型前设置了 seed，不能把这个问题扩展成“全部扫描失效”。

`py/train.py:48` 只保存 model/itos/meta；`:152` 明确输出 no retraining。实测 resume 前后 step 都是 1，退出码却为 0。splits 训练的恢复还会按 meta.corpus 去 corpus.json 找桶，不能正确还原数据来源。

先固定 seed，再构造模型；隔离 batch/sample RNG。训练快照保存 optimizer、调度配置和位置、Python/Torch/CUDA RNG、数据/tokenizer/config 身份、步数与已见 token 数。明确 --steps 是目标总步数还是追加步数。保存采用临时文件加原子替换，并区分 latest/best。

[PyTorch 官方说明](https://docs.pytorch.org/tutorials/beginner/saving_loading_models)也明确区分只存模型权重与可恢复训练的通用 checkpoint；本项目还需保存自有采样器状态。

### A4 · P0：数据审计没有成为训练入口的门槛

当前 manifest：**14,121 条、55,107,977 字**；发现 **292 组相同哈希、550 条额外重复记录**。所有正文存在且与记录哈希相符；当前没有发现相同哈希跨 split。不能据此宣称所有近似重复、选集重收、父故事变体均已排除。

`data/split_audit.json` 是 ok=false（550 条 issue），`data/split_report.json` 却是 ok=true。后者主要验证数目/字数守恒，`build_splits.py` 没有将前者的重复问题作为失败条件。

`prepare.py:68` 用顺序编号生成 story_id，`:122` 按当前池 hash 排序后切比例：增加作品可能改变 ID 和既有切分。需要 stable work_id、parent/group_id、固定 split manifest、全文与近重复分组、显式失败退出码。

README 标记 localugc 为隔离学习桶，但 build_splits 和 POOLED 会装配全部桶，包括 localugc。应以 purpose=learning/release/evaluation 及 allowlist 控制用途，而非仅靠 README。这里建议的是落实项目自己的数据用途约定，本轮没有重新认定各来源法律状态。

### A5 · P0：缓存可以静默复用旧数据结果

`sweep_worksplit.py:253` 和 `:464` 主要凭文件名/存在性复用结果；模型文件名没有 lr/epochs/batch/data hash，trigram 缓存缺少 tokenizer/data/protocol 身份。相同 tag 改配置、增补语料再运行，可能读到旧结果。

实例：当前 gudian manifest 为 train 44 / test 6 部；历史 5M 结果记录 train 29 / test 5 部、V=6379。历史结果本身可以保留，但现行命令不能证明能复现其数据版本。`--report_only` 只按 tag 收集也不足以阻止混合协议。

引入 run_fingerprint，覆盖代码（含未提交 diff）、完整解析配置、训练/验证切片、tokenizer、评测目标位置与解码设置。缓存必须逐项校验，历史无指纹结果进入 legacy 空间。

### A6 · P1：test 已被用于探索和调参

train.py 的 --splits 读取 train/test，未读取 val；扫描按 test 画多点曲线、比较容量和预算，trigram 还有明确标注的 alpha_best_on_test。透明标注优于隐瞒，但不恢复 test 的盲测资格。

将当前结果标记为探索结果；新实验用 val 做早停、alpha 和超参选择。新增真正未用过的锁定作品/故事家族，最终只跑预注册版本。少量作品里的连续字符不是独立样本，应按作品/故事报告分布与 bootstrap 区间，不能把 5 万 token 当 5 万个独立观测。

### A7 · P1：泄漏实验测到了直接训练文本重叠

`sweep_worksplit.py:443–446` 从训练区的 90% 处切 leak_ids；常见单档 200k 场景，ids_all 到 200k 为止，leak_ids 就是训练集最后 20k。现有 leakprobe 结果也记录 leaky_test_chars=20000。

因此 +33.5pt / +6.1pt / 5.5 倍是“训练内片段与作品外留出”的混合差异，不能当作“同作品但正文未见”的纯泄漏效应。实践篇24、发布说明、对应实验报告应更正解释并保留旧证据。

重做三组：训练内片段、同作品未训练片段、不同作品未训练片段；后两者目标区间必须与训练完全不重叠，同时报告文本域差异。词表、目标位置数、训练预算固定。不要先假设三组一定单调。

### A8 · P1：数据量实验混入作品组成和优化预算变化

训练集按 story_id 拼接，扫描使用 ids_all[:size]。小档可能主要是首部作品，大档逐渐引入其他作品，所以不是只增加样本数量。固定 epoch 跨数据量时总 token/steps 本就变化，也不是跨数据量 compute-matched。

实践篇31和实验报告把小数据上的 1172 步“够用阈值”搬到 5M，进而宣称“排除预算”“加步数无用”，证据不足。文章自身也承认更严格对照尚未跑。实际 5M 日志是 7324 步，并非 7325；复现命令 --tags 应为 --tag，且还需指定 ctx=64、桶、种子、数据版本等。

新增固定作品混合比例的嵌套采样；做数据量×训练预算小网格，在相同数据上增加预算，在相同预算下改变数据量。记录总训练 token、更新步数、学习率曲线和各作品曝光量。固定 epoch 对比可以保留，但只能按其真实含义解释。

### A9 · P1：生成模型接口还不适合完整故事

默认只保留最近 32 字，没有大纲条件训练；长提示被截断且用户看不到真正输入。0 同时是 UNK，并在 `eval_story.py:85` 被当作停止信号；没有独立 EOS 的完整故事训练。采样没有 CLI seed，使用全局 RNG。

分离 UNK/BOS/EOS/PAD，训练显式文档/场景边界；长度不足应透明返回原因；每个 prompt 使用独立采样 seed。生成返回停止原因、截断信息和正文，不混入提示。`tokenizer.py` 目前是独立学习实验，训练和推理仍调用字符编码；其最长匹配编码不能直接视为标准 merge-rank BPE，且没有字节回退。

### A10 · P2：性能与完成状态容易误导排期

benchmark.py 的 chars_per_sec 少乘 ctx；tracemalloc 主要记录 Python 分配，不能代表 PyTorch 原生张量/GPU 峰值。预热后重置 seed/optimizer 并未恢复权重，不应把后续质量称为严格从零训练。扩容前补 RSS、CUDA memory、计时同步和完整有效 token 统计。

V1 TODO 的 P1–P4 总标题/验收有完成标记，但 resume、SFT、场景管线、盲评、手机验收仍未做。README 的数据规模、下一步与发布顺序也有多处过时。统一区分“脚本存在、功能跑通、测试通过、能力达标、已发布”。

## 4. “能自己写小说”的可验收定义

将两种交付身份单独记录：A 为自研随机初始化模型，B 为预训练模型微调/辅助写作系统。B 可以较快验证交互与编排价值，但其输出不能归到 A 名下。用户的自研模型目标继续作为主线。

建议先冻结以下阶段门槛；具体数值是项目验收目标，不是已达成结果或模型能力保证。

| 阶段 | 用户输入与模型输出 | 验收门槛建议 |
|---|---|---|
| M0 可靠实验 | 一个配置生成可追溯 checkpoint 和报告 | 同环境同 seed 可复现；断点续训等价；数据审计失败不能训练；评测不计提示词 |
| M1 完整场景 | 2–3 人物、一个冲突 → 300–800 字 | 30 个开发场景之外另设锁定集；完整输出率≥90%；人工评定“冲突发生且有结果”≥70%；重大设定矛盾≤10% |
| M2 条件写作 | 人物卡+事件大纲 → 800–1500 字 | 事件完成≥80%；两名读者匿名对比并报告平局/分歧；SFT 相对其基座的改进有区间和原文支撑 |
| M3 完整短篇 | 用户给创意 → 3–5 场景、约 3000–8000 字 | 人物目标可追踪、事件有因果、承诺的主要冲突有收束；跨场景状态矛盾逐条审查；同题复跑不会崩溃或无限循环 |
| M4 多章小说 | 简介+设定 → 可暂停、恢复、导出的多章稿 | 章节依赖、时间线、伏笔、人物状态可核对；扩大到数万字必须新增长程评测，不以字数代替质量 |

M1 失败先分辨基础语言能力、任务理解、数据质量与上下文不足，不能直接用多 Agent/强制模板把失败掩盖。Top-1 超过 trigram 不是任何小说阶段的充分条件。

## 5. 推荐实现路径与架构

保留 minilm.js / minilm_torch.py 的 parity 默认路径。将可扩展训练器、tokenizer 接口和数据集实现拆开，避免学习对齐实验被新架构不断破坏。

第一步保留字符模型修复可靠性，然后在固定数据上对照成熟 tokenizer，记录 OOV、字符/token、总参数、正文可用上下文和吞吐。不同 tokenizer 不直接比较 token PPL；若实现统一文本 bits/byte，需定义特殊 token 与归一化口径。

自研训练先建数百条人工可审阅的受限中文完整故事作数据管线小样，验证结构和去重后再扩到数千/数万；这些数量不保证训练成功。角色少、时间线短、单一冲突、明确结果；保留体裁/事件/人物组合多样性。合成数据记录 teacher、prompt、版本、parent_id；同家族不能跨 split。故事全文反抽大纲只用于训练，锁定评测输入不偷带结局答案。

模型规模采取逐档实测：约 1–3M 验证新训练器与完整故事，再评估 10–30M 是否值得投入。ctx 从 256/512 起验证，进入条件写作前确保人物卡、大纲和目标正文能够容纳，再考虑 1024/2048。它们是候选实验档位，不是足够写小说的承诺。先测候选配置吞吐/内存，再决定硬件和总 token 预算；本机当前 torch 为 2.14.0+cpu、CUDA 不可用。

数据缓存采用预编码数组/分片，减少 Python list 重复编码；实现 batch 数据加载、梯度累计、按设备选择混合精度、AdamW 与明确调度。训练器支持阶段保存、验证、早停和取消。不要同时更换 tokenizer、全部架构和数据后再把改善归因于某一个变化。

SFT 数据格式：setting、characters、state_before、outline、target_text、state_after、parent_id。输入部分 loss mask=-100，只对目标正文及必要终止 token 学习。先验证一批样本 mask/shift 正确，再跑正式数据。

小说管线建议固定顺序执行：

1. 创意与设定生成全篇大纲及各场景目标。
2. 根据 scene_id 提取本场需要的人物事实、历史摘要、未完成事件。
3. Writer 生成本场正文，保存原始版本。
4. 检查事件、矛盾、重复与训练文本匹配；需要时有限重写，保留修改原因。
5. 验收后的场景才更新人物/时间线/伏笔状态，然后进入下一场景。
6. 汇总全文、检查结尾收束，导出正文、设定表和实验报告。

同一模型可以承担不同步骤，不要求多个 Agent。状态记录要有正文证据位置；未确认的推断不能写成已发生事实。先建立基座/基座+管线/SFT/SFT+管线四组，再单列自研结果。选基座时核实当时的模型卡、许可、中文表现与硬件需求，不沿用旧文档估价。

## 6. 数据、接口、工作流与界面影响

新增统一 run 目录：config.json、provenance.json、metrics.jsonl、samples.jsonl、checkpoints、eval_report.json、article_evidence.json。run_id 与数据/模型/tokenizer/代码版本绑定；失败实验也留记录，不覆盖历史数字。

小说项目持久化 project_id、outline_version、scene_id、state_version、checkpoint_id、status、attempt、input_hash、output_hash、evidence。状态取 planned/writing/reviewing/accepted/failed/cancelled。重试按 scene_id+input_hash 幂等；取消后允许从最近 accepted 场景恢复。

本阶段以 CLI/本地文件为实现入口，无需数据库迁移或新 HTTP API。训练用日志和 checkpoint；生成用逐场景事件日志。未来接 Web 服务时再增加 job_id、SSE、断线恢复和取消接口。

浏览器继续承担教学与成果阅读：用户可查看训练快照、全文样本、失败对照、实验配置及下载。模型家族、自研/基座身份、真实 prompt 截断、是否预录都需可见。360/390px 下测试生成/停止/复制、长正文阅读和图表滚动；DOM 桩不是布局验收。大训练不放进手机主线程。

正文使用“实验观察 → 可能解释 → 尚不能排除的原因”三段式。例：可以说“本次 5M/3epoch 配置下模型 Top-1 边距变差”，不能说“已经证明大数据阶段优化预算无关”。[TinyStories 原论文](https://arxiv.org/abs/2305.07759)支持研究受限英文故事数据与小模型，但不能直接证明中文长篇所需规模、预算和质量。

建议下一批文章与功能一一对应：

| 实验交付 | 文章题目建议 | 必须带的证据 |
|---|---|---|
| 评测修复 | 模型一字没写，为什么拿到了人物分 | 空输出反例、修复前后评分、JSONL 校验 |
| 真正续训 | 关掉训练再打开，模型真的接着学了吗 | 连续训练/中断恢复的权重与下一步批次对照 |
| 数据治理 | 五千万字里面，有多少才是独立故事 | 去重、作品/家族统计、固定 split 身份 |
| 单场景基线 | 模型第一次写完一场有结果的戏 | 全部锁定场景、完整失败样本、人评表 |
| SFT | 它会接着写，但听不懂我的大纲 | 同基座同数据身份、loss mask、事件完成对照 |
| 多场景状态 | 第三场戏里，它还记得第一场的承诺吗 | 时间线、状态证据、矛盾和修订记录 |

每次实验输出一张证据卡：问题、唯一主要变化、其他变化、run_id、数据身份、实际预算、结果表、完整样本入口、失败案例、结论边界、复现命令。由证据卡生成文章草稿，事实核对后再人工编辑发布；不自动把草稿写成亲历或实验成功。

内容状态为 draft/evidence_verified/editor_reviewed/published，并记录文章引用的 claim_id 与 run_id。数字表自动生成，命令在隔离目录验证；内容 lint 继续检查结构，新增“命令参数存在、数据身份齐全、引用数值一致”检查。选取 4–6 篇打磨后发布，再依据读者问题调整顺序；本轮没有代为公网发布。
