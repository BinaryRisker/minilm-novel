# 一次训练的账本：数据量、步数、种子和存档

**系列：从零训练中文小说模型｜第 10 篇（原理篇）**
**前置阅读：原理篇 9；不熟悉的术语可回阅读地图查询**

更新：2026-09-17。本文先讲通用原理，再说明本项目怎样实现；算例均标明用途。

“我训练了一小时”不能告诉别人模型学了多少。机器速度不同，批次和长度也不同。要把训练看成一本账：用了哪份数据，每次看多少，更新几次，保存了什么。

## 四个容易混淆的量

| 名称 | 含义 | 示例 |
|---|---|---|
| context | 一段练习的 token 长度 | 32 |
| batch | 一次计算中的段数 | 8 |
| step | 一次优化器更新 | 400 步 |
| epoch | 一次完整数据遍历；随机采样时常报等效值 | 曝光量除以数据量 |

单卡、无 padding、无 loss mask、无累积时，8×32×400=102400 个目标 token 曝光。若训练文本有 2000 token，等效约 51.2 epoch。但随机窗口会重复或漏读位置，不能声称每个字恰好读了 51 遍。

有梯度累积时，近似曝光量还要乘 accum；多卡还要按实际全局 batch 计算。独立数据量与累计曝光量要分别报：把同一故事读一百遍，没有得到一百篇新故事。

## 多训练可能发生什么

训练 loss 持续降低而验证 loss 回升，是过拟合的常见信号。两个都高，也可能是训练不足、学习率不合适、数据问题或容量不足，不能只凭一条曲线唯一归因。

调上下文时尤其要记账。固定 batch 和曝光 token，长度翻倍通常使更新步数减少；此时效果变化不能全部归功于上下文。先明确控制步数、token 还是实际计算时间。

## 随机种子管得住什么

种子是随机序列的起点，要在模型初始化之前设置，还要覆盖实际使用的数据采样流。相同 seed 不保证不同设备、软件版本和并行算法逐位一致。几个种子的波动也不代表换一批测试作品的波动。

## checkpoint 现在存什么

当前 `py/checkpoint.py` 的 v2 格式保存 model、opt、itos、meta、step、rng：权重、优化器、词表、配置元数据、当前步数、随机状态。学习率计划由 metadata 和调度函数恢复，并非单独序列化一个 scheduler 对象。

旧稿“Python 只能存权重、resume 不训练”描述的是修复前。当前已有真实续训及小规模 CPU 等价性验证，但不能据此宣布所有 GPU 与大数据配置都验证过。

验证恢复时，先约定总共 160 步，80 步时中断，再继续到 160；与一次跑完比较。若先按 80 步设计学习率，后来改成 160，前半程调度已经不同。保存字段齐全也只是前提，还要检查配置、数据指纹、下一批数据和最终结果。
