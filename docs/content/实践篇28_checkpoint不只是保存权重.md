# checkpoint 不只是保存权重：现在怎样正确恢复训练

checkpoint 是训练存档。只保存模型权重，足够支持一部分推理任务，却通常不够原样继续训练：优化器有自己的历史，采样器也有下一批数据的位置。

## 旧问题已经修过

早期 `py/train.py` 只存 model/itos/meta，`--resume` 仅加载评测。旧文章描述的是当时缺陷，不能继续当作现行使用说明。当前 v2 契约由 `py/checkpoint.py` 统一实现：

| 字段 | 存什么 | 为什么需要 |
|---|---|---|
| model | 模型权重 | 恢复预测器 |
| opt | Adam 等优化器状态 | 接续之前的更新轨迹 |
| itos | 编号对应的字符 | 保持文本和权重对应 |
| meta | 配置、计划与数据信息 | 重建相同训练条件 |
| step | 已完成的更新次数 | 从正确位置继续 |
| rng | 随机状态 | 恢复相应随机流 |

学习率调度由 step、计划总步数及代码重建。分片训练的数据抽样按种子和步数派生；不能只因没单独保存一个“游标字段”就断言它必错，关键是下一批是否等价。

## 正确的比较方式

先计划总共 160 步，第一次在 80 步中断，之后恢复到 160。与相同起点的一次跑完比较。第一阶段若本来只计划 80 步，后来改成 160，余弦学习率前半段就不同了。

```text
A：同一起点 ───────────────→ 160
B：同一起点 → 80 → 保存/恢复 → 160
```

实践篇 33 与 `dev/verify/verify_resume.json` 记录了小规模 CPU 测试：完整状态恢复的末步参数最大差值为 0，丢失状态的对照产生漂移。这是特定环境的历史证据，不是跨设备或长训练的通用保证。

## 当前入口仍有边界

旧 `train.py` 的 `--bucket` 路径可以重建作品数据；它的 `--splits` 自定义目录恢复分支却没有按保存的目录重读，不能把它当成可靠续训教程。新手实操使用 `--bucket` 并明确前置数据条件。

新分片训练器复用了存档契约，但还需核对 train/val 词表一致、数据指纹、配置以及目标 GPU 的严格恢复测试。加载成功和继续出现 loss 只是第一步。旧格式缺少 opt/rng 时，程序会告警，也不能宣称精确恢复。

## 文件越多不代表备份越安全

当前快照可能反复写同一个 checkpoint.pt。要比较中途状态，先备份到独立文件，再续训；不要拿已被末步覆盖的文件做“中途恢复实验”。每次实验也应使用新的输出目录。
