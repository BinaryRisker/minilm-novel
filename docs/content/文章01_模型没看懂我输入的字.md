# 我发现模型没看懂我输入的字

**系列：从零训练中文小说模型｜第 1 篇**

实验身份：model=MiniLM-char-v1｜corpus=记忆之海(2,668字)｜split=前90%/后10%｜params=55,400｜seed=编码示例｜steps=400｜protocol=统一协议(eval/protocol.js)

我给一个 5.5 万参数的中文模型输入：

> 警察敲了敲门，

模型真正看到的，却不是这句话。

## 模型实际收到什么

这个实验台使用字符级分词。词表只包含训练语料里出现过的字符，没见过的字统一映射为 0 号未知 token。

这句话被编码成：

```text
[0, 0, 0, 20, 0, 347, 363]
```

其中“警”“察”“敲”是当前词表外字符；“门”和逗号仍然有自己的 token id。为了让展示更直观，解码器会跳过未知 token，于是页面上看见的输入像是：

```text
了门，
```

这不是模型理解了“警察敲了敲门”，而是它在缺少关键信息的情况下，继续根据“了”“门”“，”和训练语料里的统计规律猜下去。

这件事不是个例。下面三个训练集外的提示词，模型实际能接收到的信息各不相同：

| 输入的提示词 | 词表外字符 | 模型真正看到的 |
|---|---|---|
| 警察敲了敲门， | 警、察、敲（4 个字位） | 了门， |
| 他打开冰箱， | 冰、箱 | 他打开， |
| 今天的天气真 | 真 | 今天的天气 |

规律很直白：**字越冷门，模型接收到的信息越少，后面的输出就越不能算「它理解了这句话」。** 所以比较生成质量之前，得先确认模型到底收到了什么。

顺带说清一个容易被忽略的代价：**词表越小，陌生字越多。** 三段原创语料的唯一字符数分别是 364 / 304 / 323，也就是说词表只有三百多。任何一段没见过的现代生活用语——冰箱、电脑、警察——都会立刻撞在词表边界上。这不是 bug，是字符级方案在这个语料规模下的固有属性。

## 这件事为什么重要

如果我只展示一段看起来还算通顺的续写，很容易把“模型输出没有崩”误认为“模型理解了提示”。但输入已经被改变，后面的生成就不能被解释为完整语义上的泛化。

这也是小模型实验里很容易被忽略的地方：评测不只要看输出，还要看模型到底收到了什么。否则我们比较的可能不是两个模型，而是两个不同的输入。

## 我做了什么修复

现在实验台会逐字显示：原字符、token id、是否 OOV，以及模型实际使用的 id 序列。遇到陌生字时，页面会明确提示，而不是静默跳过。

下一步会比较字符级分词和带字节回退的子词分词，重点观察三件事：输入覆盖率、词表参数开销和语料外提示词的生成质量。当前文章只证明输入被改变，不证明子词分词一定会提高写作质量。

如果你想复现，打开项目里的 `index.html`，在生成面板输入一条训练语料没有出现过的句子，再看 token 映射面板。你会发现，语言模型的第一步不是“写作”，而是把文字变成一串数字。
