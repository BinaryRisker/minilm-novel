# 一个陌生字被替换成 UNK 之后，模型还算理解原句吗

**系列：从零训练中文小说模型｜第 27 篇（实践篇·模型拆解课）**
**前置阅读：原理篇 2（字怎么变成数字：词表、OOV 与 UNK）**

实验身份：model=MiniLM-char-v1｜词表 min_freq=3｜UNK=0 号位｜留出切片 UNK 占比 0.036%~0.72%｜protocol=作品级切分

实践篇第 1 篇写过：输入「警察敲了敲门，」时，模型真正看到的是「了门，」。这一篇要回答一个更难的问题——**替换之后，我们还剩多少资格说它「理解了这句话」？**

## 现在词表长大了，但问题没消失

原始三段手写语料的词表只有 201 个字（含 UNK），所以冰箱、电脑、警察这类词一进来就撞墙。换成公版大语料后，词表按 `min_freq=3` 裁剪，规模变成：

| 桶 | 词表 V |
|---|---:|
| `story` 短故事 | 1,769 |
| `scifi` 科幻 | 3,741 |
| `wuxia` 武侠 | 5,182 |
| `gudian` 古典 | 6,379 |

而 UNK 的实际占比，报告里给的是一个**跨桶区间**，没有逐桶拆分：**各桶留出切片的 UNK 占比在 0.036% ~ 0.72% 之间，其中 `story` 的 0.72% 最高**（它的词表最小）。也就是说，被压成 UNK 的位置通常不到百分之一——听起来无害，直到你正好想知道那个字是什么。

`min_freq=3` 的意思是：**在这部训练池里出现少于 3 次的字，一律不进词表，映射到 0 号 UNK。** 它换来的是可控的词表规模（不然长尾字会把嵌入表撑爆，见实践篇第 26 篇），代价是把长尾字全压成同一个符号。

## 真正的麻烦不是「丢字」，是「丢的字不可分辨」

「他打开冰箱」和「他打开冰柜」被裁成同一个序列时，模型收到的输入**完全相同**。这时：

- 它不可能区分这两句——不是能力不够，是**信息在进模型之前就已经被抹掉了**；
- 更隐蔽的是，UNK 是有概率分布的：它会被训成「所有低频字的平均行为」，于是模型在 UNK 位置上倾向于吐出高频接字。

所以 UNK 不是「少了一个字」，而是**用一个高频符号替换了一个我们不知道是什么的字**。

## 我们能测什么，不能测什么

诚实地列一下：

| 问题 | 现在能回答吗 | 依据 |
|---|---|---|
| 输入被改变了吗 | ✅ 能 | 逐字 token 映射面板（tokMap） |
| 改变的比例有多大 | ✅ 能 | UNK 占比 0.036%~0.72% |
| 改变后评测还公平吗 | ✅ 能 | 模型与 trigram 用**同一份词表**，比较成立 |
| 改变后模型还「懂原句」吗 | ❌ 不能 | 没有任何语义保持的测量 |

第三行值得强调：**UNK 不影响「模型 vs 基线」的相对比较**——两者看到的是同一串被压扁的输入。但它**绝对影响**「模型是否理解这句话」这类绝对断言。

第四行是真正的缺口。我们目前没有任何一个指标能回答它。

## 一个很便宜的可证伪实验

要测「替换后还算不算理解原句」，不需要新架构：

1. 取一批句子，人工标注它们的关键信息（谁 / 做了什么 / 结果）；
2. 三个版本对照输入：**原句**、**把关键词替换成 UNK**、**替换成一个随机已登录字**；
3. 比较模型下一步的候选分布差异（KL 散度或 Top-5 重合度）。

如果 UNK 版和原句版的分布差异 ≈ 随机字版的差异，说明模型对这两个位置的处置没有区别，那「理解原句」这个说法就该收回。**这个实验用现成的 `generate()` trace 就能跑**，是本项目目前性价比最高的待办之一。

## 一句话

在未登录字上，我们只能主张「模型对同一份被压扁的输入做了一致的处理」，**不能主张「它理解了你想说的话」**。前者是可测的，后者目前不可测。

**可复现入口**：`index.html` 的 tokMap 面板；词表构建 `py/minilm_torch.py::build_vocab(min_freq=3)`。
