## 这轮核查发现的使用限制

1. `py/novellm/dataset.py build --split val` 会对指定 split 调用词表拟合。**不能分别运行 train/val build 后假定词表相同。** 应先在 train 拟合一次，通过 `build_shards` API 把同一份 itos 传给两个 split，见训练手册。本轮只说明问题，没有修改训练代码。
2. `py/train.py --splits` 的恢复分支没有按保存的 splits 目录重建数据。入门续训示例使用 `--bucket`，不推荐自定义 splits 恢复路径。
3. 旧 `train.py` 到计划终点会读取 test；`eval_story.py` 默认留出出题路径也使用 test。教学练习只能当探索，不能反复运行后又把这些 test 称为最终盲测。新分片训练器的 train/val 路径更适合后续正式选型。
4. 当前新训练器未实现旧手册设想的全部 EOS/PAD、专用 loss mask、BPE 和独立 final_eval 流程。命令名称和计划架构不能替代代码检查。
5. 本轮 CPU 教程运行时，解析器提示 v3 与主清单不是同一批作品，日志称回退，但本次 meta 实际记录最终选择 `manifest_v2.jsonl`、`near_dup_merged=True`；不能把中间提示当最终身份。是否全库干净仍需对应审计。**因此本轮只验证教学命令，不报告干净测试或模型能力结论。**

## 哪些内容应该长期保留

原始 run JSON、实验日志、历版 PRD/TODO 应保留时间线。修正解释时，不应把旧实验数字换成今天的值，伪装成同一次实验。

实践篇保留的历史数字，是理解“如何发现问题”的材料。精确复现还需要当时 commit、正文、词表、切分和依赖；运行今天的同名命令可能得到另一组结果。过时的是“当前状态”与超出证据的结论，不是日期较早就自动没有价值。
