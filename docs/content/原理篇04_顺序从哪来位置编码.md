# 同样几个字，顺序为什么重要

**系列：从零训练中文小说模型｜第 4 篇（原理篇）**
**前置阅读：原理篇 3；不熟悉的术语可回阅读地图查询**

更新：2026-09-17。本文先讲通用原理，再说明本项目怎样实现；算例均标明用途。

“我追你”和“你追我”用了同样的字，意思却不同。字的嵌入回答“是什么字”，还需要某种信号表达“出现在什么位置”。

## 本项目用一张位置表

每个位置也有一行可学习的数字。输入模型时，将词向量与位置向量逐项相加：

```text
位置 0 的输入 = “我”的向量 + 位置 0 的向量
位置 1 的输入 = “追”的向量 + 位置 1 的向量
位置 2 的输入 = “你”的向量 + 位置 2 的向量
```

这里的位置是当前窗口里的位置，不是字符的词表编号，也不是整部小说的绝对页码。相加保持表示宽度不变；拼接也可以设计，但需要调整后续结构，其开销不能笼统说成“刚好翻倍”。

## 没有位置表，就一定完全不知道顺序吗

不能这样说。无位置编码、无掩码的自注意力具有排列等变性，但因果掩码会让不同位置看到不同长度的前缀，已经引入结构上的不对称。因此不能断言“取消位置表后，所有相同字组成的句子都完全一样”。

加入显式位置信号能帮助模型表示顺序和距离；它在某个任务里改善多少，仍应在固定数据和预算下实测。原项目的小样本消融没有充分统计证据证明普遍收益或普遍无效。

## 常见位置方案

| 方案 | 简单解释 | 当前项目 |
|---|---|---|
| 学习式绝对位置 | 每个位置一行可训练数字 | 主要模型实际使用 |
| 正弦位置编码 | 用固定函数生成位置向量 | 不是当前主实现 |
| RoPE | 对注意力的 Q/K 施加与位置有关的旋转 | 旧设计文档提过，当前主实现未采用 |

不能因为方案更新，就认定它必然适合这次实验；也不能把设计方案写成已经运行的模型结构。

## 上下文长度有什么限制

如果位置表只分配 32 行，原模型不能直接输入 64 个位置。扩大表并重新训练或做专门适配，是另一次工程任务。生成时可以一直续写，但常见滑动窗口只保留最近的一段前文：能写出一万字不等于始终记住最初的人物设定。

因此在浏览器中改变 ctx 后，应重新初始化并训练；不能把新的配置数字当成旧权重自动获得的新能力。
