# 三个随机种子就够了吗？我不再相信单次 benchmark

**系列：从零训练中文小说模型｜第 8 篇（实验室周报）**

实验身份：model=MiniLM-char-v1｜corpus=三语料｜seeds=JS×3 / PyTorch×5｜steps=400｜protocol=统一协议(eval/protocol.js)

如果我只给你一个数字——「武侠语料留出集 Top-1 = 24.0%」——你会怎么理解它？

我曾经也这么用数字。直到我把种子数加上去，才发现这个数字在骗人。

## 同一个模型，不同种子，能差多少

固定模型配置（ctx=32、d=40、2 层、4 头）、固定 400 步、固定语料，只换随机种子，武侠语料的留出集 Top-1 是这样的：

| 种子 | 武侠 Top-1 |
|---|---:|
| 42（单次原始值） | 24.0% |
| 多次运行均值 | 19.8% ± 0.5% |

那次「24.0%」落在均值 **4σ 之外**——它不是「典型表现」，它是一次幸运抽样。如果拿它去和另一侧实现的单次值对比，会得出「两个实现差 4.7pt」的结论；而这 4.7pt 是抽样运气，不是实现差异。

都市语料同理：单次 40.6% 偏向高端，稳态其实更低。

## 那到底要看几个种子

我的做法从「跑一次」改成了「看分布」：
换成分布对比之后，JS 与 PyTorch 两个实现的结论是这样的：损失曲线全程偏差 ≤ 0.030；Top-1 均值差 科幻 1.2pt / 武侠 1.4pt / 都市 2.8pt，全部落在 2×σ_pool 以内。

**注意这里换了问题。** 原来问「两个实现差多少个百分点」，现在问「这个差，比同一个实现换种子的波动大吗」。后者才是能回答「是不是同一个模型」的问题。


- JS 侧换 3 个种子，PyTorch 侧换 5 个种子；
- 比较时先算「同一个实现换种子」的波动 σ_pool；
- 判据从「差距 < 2pt」改成 **均值差 ≤ 2 × σ_pool**。

为什么用 2σ 而不是「看一眼差不多」？因为实现之间的差距必须和同一实现换种子的波动放在同一把尺子上比较。这里的 2σ 是本项目的探索性判据，不是统计显著性的通用替代品。

## 一个更重要的反转

最早我定的判据是「两个实现差距 < 2pt 就算对齐」。结果第一版对不齐——但真正的问题不是实现写错了，而是我的判据本身错了：实现之间的差距，必须和「同一个实现换种子」的波动去比，才有意义。

科学的过程不是「证明我是对的」，而是「提出一个可证伪的判据 → 看它被数据打脸 → 换成更诚实的判据」。这条路比结论本身更值钱。

## 结论边界

- 单次 benchmark **不可信**，没有种子数的对比数字尤其不可信（这条也适用于你读别人的评测）；
- 三个种子够不够？对一次小模型教学实验，**3~5 个并报告均值±σ** 可以作为最低探索起点；它不能替代更大样本、更严格的统计检验，也不能单独支撑能力结论；
- 本结论基于固定配置、固定语料、固定 400 步，换配置后 σ 会变。

**可复现入口**：`py/sweep_data_scale.py` 与 `py/align_report.md` 用的就是「多种子 + 分布对比」的协议；你自己跑时把种子循环起来，别只看第一条。
