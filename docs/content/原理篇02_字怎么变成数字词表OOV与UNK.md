# 字怎么变成数字：词表、OOV 与 UNK

**系列：从零训练中文小说模型｜第 2 篇（原理篇）**
**前置阅读：原理篇 1（全景：一个小说模型有哪些零件）**

实验身份：model=MiniLM-char-v1｜词表=按语料构建 min_freq=3｜UNK=0 号位｜V=201（原始手写语料）~ 6,379（古典桶）｜留出切片 UNK 占比 0.036%~0.72%｜protocol=作品级切分（2026-09-14 Day-2 报告）

模型不认识字，只认识数字——所以动笔之前，得先办一场**入学登记**。本篇把登记规则讲清楚，顺便解释一个你可能见过的灵异现象（实践篇第 1 篇）：给模型输入「警察敲了敲门，」，它实际收到的是：

```text
[0, 0, 0, 20, 0, 347, 363]
```

页面上甚至只剩「了门，」三个字。哪来的三个 0？警察去哪了？往下看。

## 三个名词，一次讲完

| 名词 | 大白话 | 在这个例子里 |
|---|---|---|
| 词表 | 模型的**点名册**：训练语料里出现过的每个字，按出场次数排座次领编号。本项目字符级分词，一个字 = 一个 token | 「门」= 20，「，」= 347 |
| OOV | out-of-vocabulary，**点名册上没有的生面孔**。描述「查无此人」这个状态 | 警、察、敲 |
| UNK | unknown，生面孔的统一去向：全部塞进 **0 号座位**，无论你是「警」还是「鲨」 | 开头那三个 0 |

一句话记住后两个的关系：**OOV 是状态（查无此人），UNK 是处置（请坐 0 号位）。** 一个字 OOV 了，进模型时就变成 UNK。

所以「警察」失踪不是灵异事件，是传话游戏：托人带话「警察敲了敲门」，带话的人不认识这三个字，张嘴就成了「了门，」——话没全丢，但关键信息没了。

## 点名册是怎么造的

`build_vocab` 三步：统计语料里每个字的出现次数 → 按次数排座次（0 号永远留给 UNK）→ 出场少于 `min_freq=3` 次的，不给学籍。

为什么不照单全收？因为只来过一次的「影子同学」太多的话，名册会比教材还厚，直接把下一站的查找表撑爆（这笔账原理篇 3 算）。裁剪的代价是：所有低频字挤同一个 0 号座。词表随语料长大：

| 语料 | 词表 V |
|---|---:|
| 原始手写语料（记忆之海） | 201 |
| story 短故事 | 1,769 |
| scifi 科幻 | 3,741 |
| wuxia 武侠 | 5,182 |
| gudian 古典 | 6,379 |

换上公版大语料后，被塞进 0 号座的比例其实不高：各桶留出切片的 UNK 占比 **0.036%~0.72%**，`story` 最高（0.72%，它名册最短）。听上去无害——直到你正好想知道那个字是什么。

## 挤一个座位的真正代价：不可分辨

「他打开冰箱」和「他打开冰柜」，如果「箱」「柜」都是生面孔，模型收到的输入**一模一样**。不是它笨，是信息在门口就被门卫拦下了。于是有条线必须划清楚：

- 模型 vs trigram 的**相对比较**依然成立：两位考生拿的是同一份被压扁的卷子（同一个词表），输赢不作弊；
- 但「模型理解了你这句话」这种**绝对断言**不成立：没有任何测量证明替换前后它想的一样（实践篇第 27 篇）。

UNK 还有个阴险的小习惯：它会被训成「所有低频字的平均行为」，于是模型在 UNK 位置上爱吐高频接字。它不是「少了一个字」，是**让一个万金油顶替了一个我们不知道是谁的字**。

## 在哪里亲眼看

`index.html` 的 tokMap 面板：输入任意一句话，逐字显示原字符、编号、是否生面孔。打一句它没见过的现代话（冰箱、电脑、警察），看它们齐刷刷变 0，而「的了，」稳如老狗。
