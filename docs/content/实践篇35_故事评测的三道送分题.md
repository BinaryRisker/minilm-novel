前几轮修完了种子、续训与数据隔离。最后一块是**生成侧**：模型能不能写出像样的故事，我们凭什么这么说？打开 `py/eval_story.py` 自检，发现了三道送分题——**每一道都让分数看起来比实际好。**

## 三道送分题

| 问题 | 修复前的行为 | 后果 |
|---|---|---|
| 出题来源不明 | 默认提示词文件 `历史规划中的提示词文件（当前出题入口见 `py/eval_story.py`）` **根本不存在**（脚本开箱不能跑）；即使有，也可能来自训练过的作品 | 自问自答，重复率/新颖度全部失真 |
| 采样不可复现 | 用 `torch.multinomial` 采样解码，**一个种子都没设** | 同一 checkpoint 两次生成不同，结论无法复核 |
| 指标算在提示词上 | 事实检查/事件完成度在 `prompt + 生成` 上算；`generated_chars` 把提示词也算了进去 | 提示词里的关键词必然命中 → 送分 |

## 送了多少分：把两个口径并排算一遍

我构造了一组「关键词只出现在提示词里」的样本（事实关键词：莉莉、公园；事件：他们喜欢在公园骑自行车），对同一批生成结果算两个口径：

| 指标 | 旧口径（提示词 + 生成） | 新口径（仅生成段） |
|---|---|---|
| 事件完成度通过率 | **100%** | **0%** |
| 事实关键词通过率 | 83% | 50% |
| `generated_chars` | 160（= 提示词 40 + 生成 120） | 120 |

**事件完成度从满分掉到零分。** 旧口径那句「关键事件 100% 覆盖」完全来自提示词本身——我等于在夸模型完成了一件我替它写好的事。顺带一个实现细节：`generate()` 返回的文本**本来就含提示词**（它解码的是完整 id 序列），调用方又拼了一次提示词，于是 `generated_chars` 还虚高了一截。

## 修完之后长什么样

`py/eval_story.py` 重写，三条规矩写进实现：

1. **出题只从留出作品取**（val/test split），每条提示词记录 `story_id / 标题 / split / 偏移`，报告里可回到原文核对；也支持传人工提示词文件。
2. **`--seed` 驱动采样**，输出里记录 seed 与解码参数（temp/topk/rep_pen），每次生成前重置种子。
3. **指标只在生成段上算**，旧口径的数字另外存一份 `model_old_protocol` 作为对照——**送分幅度本身也成了可复核的产物。**

验证脚本 `py/verify_story_eval.py` 的三项判定：

```
T1 出题来源：story_001/006/009 三条全部来自 test split，在训练集里=False  ✓
T2 生成可复现：同 seed 两次逐字相同=True；换 seed 后不同=True  ✓
T3 旧口径送分：事件通过率 100% → 0%；事实通过率 83% → 50%  ✓
```

## 然后跑最小闭环，看看模型到底写成什么样

`py/closed_loop.py` 把四个阶段串起来：随机初始化 → 训练到中途（存 checkpoint）→ 断点续训到终点 → 留出评测 → 生成故事。story 桶、6 万字、600 步，整条链 47 秒跑完：

```
stage 1  step=300   val: top1=21.88% nll=4.485
stage 2  续训到 600  val: top1=21.69% nll=4.310   有效 epoch=2.56
stage 3  test（只评一次）: top1=29.83% nll=3.998
stage 4  模型       : dup4=0.056  longest_repeat=6.67  novelty4=0.657
         trigram基线: dup4=0.011  longest_repeat=2.00  novelty4=0.209
```

**这一格是本文真正的失败样本：模型输给了 trigram 基线。**

- 最长连续重复：模型平均 **6.67 字**（「妈妈妈妈妈妈妈妈爸爸爸爸」），基线 2.00 字；
- 4-gram 重复率：模型 0.056，基线 0.011；
- 4-gram 新颖度：模型 0.657 vs 基线 0.209——**模型「更原创」是因为它在瞎编**，而不是因为它会写。

真实样本（提示词「莉莉和萨姆是朋友。他们喜欢在公园骑自行车……」）：

> **模型**：拉的朋友。他们很快，有一下来来来。他们很高兴奋，有一起玩具面友。莉莉莉的妈妈妈妈妈妈妈妈妈妈妈妈爸爸爸爸爸爸妈妈妈。她不不不起来，她的，但你们喜欢。
>
> **trigram 基线**：拉，微笑着说：「妈妈，但我们可以，我们很高兴地说：「你们的口袋里。他们在公园，因为她最喜欢一起玩。」

基线写的是通顺的废话，模型写的是不通顺的废话。这跟之前几轮的大数据结论并不矛盾——**这套数据、预算与解码组合产生了较多重复，不能单凭字数与参数量唯一归因**；trigram 也可能进入重复上下文并连续重复；这次基线样本重复较少，不是结构保证。

## 边界

- 全是**自动指标**。重复率、新颖度、UNK 比例只能筛掉明显崩坏的输出，**不能替代人工盲评**——报告里的 `human_score` 字段依然是空的，等人类读者填。
- 「事实检查 / 事件完成度」是关键词匹配：同义改写会漏判，关键词碰巧出现会误判。它是过滤器，不是语义理解。
- 只跑了 story 桶 6 条提示词。gudian/wuxia 的历史文本提示词（人名、官职、地名密集）会引出另一类失败（专名错乱），本文没覆盖。
- 生成 120 字，最长重复 6.67 字是按 6 条样本平均；单条样本的方差很大（最差那条几乎整段在重复）。
- 最小闭环的语料是**截断**的（6 万字 / 桶内 800 部作品），这份数字只说明「链路通」，不代表模型能力上限。

复现：`python py/closed_loop.py --bucket story --chars 60000 --steps 600 --stop_at 300 --n_prompts 6`
原始结果：`dev/loop/closed_0915_003515/loop_report.md`（含完整样本）、`dev/verify/verify_story_eval.json`
