# 我给模型更多上下文，它反而没怎么变聪明

**系列：从零训练中文小说模型｜第 29 篇（实践篇·实验室周报）**
**前置阅读：原理篇 5（读上下文：注意力与因果掩码）、原理篇 11（评测与基线：留出集、Top-1、NLL 与 trigram）**

实验身份：model=MiniLM-char-v1（主体 40,800 + 词表 V=3,741~5,182）｜ctx ∈ {8, 16, 32, 64}｜seeds=1234,42,2024｜训练 20,000 字 / 3 epoch｜protocol=固定评测位置集（≥64 字 history，所有 ctx 档评同一批位置）

「再多给它 8 个字上下文，成绩应该上去吧？」——我一直以为会。测完才知道，**有些桶根本没动，有些桶的曲线不是单调的。**

## 一个不能跳过的协议问题

这个实验一开始就不是「拉一组 ctx 跑跑看」那么简单。原因藏在评测协议里——`py/sweep_worksplit.py` 的窗口是「**每 ctx 步一窗、窗内 history 长度 1..ctx**」。这意味着：

- ctx=8 模型**永远不评** history > 8 的位置；
- ctx=64 模型**会评** history 从 1 到 64 的全部位置；
- 两者的评测位置集合不一样。

直接拿 Top-1 比大小，就是把「更长的 history 长度」和「更多的位置」两件事缠在一起。所以本实验重新定了一组**固定评测位置**（要求前置 history ≥ 64，等距抽样），每个模型都用 `ids[p-ctx:p]` 预测 `ids[p]`——目标 token **不在**输入窗口里，所有 ctx 档评同一批位置。

| 桶 | ctx=8 | ctx=16 | ctx=32 | ctx=64 |
|---|---|---|---|---|
| scifi Top-1（mean±σ） | **6.12%** ±0.18 | 6.02% ±0.50 | 6.02% ±0.40 | 6.26% ±0.25 |
| scifi NLL | 6.600 | 6.562 | **6.547** | 6.543 |
| wuxia Top-1 | 10.82% ±0.88 | 9.74% ±0.92 | **11.61%** ±0.06 | 11.28% ±0.10 |
| wuxia NLL | 6.860 | 6.914 | **6.826** | 6.850 |

trigram 在同样位置上：scifi 8.73% · NLL 7.414；wuxia 10.50% · NLL 7.681。

## 三个直接读得到的结论

**第一，scifi 上几乎不动。** Top-1 从 6.12 到 6.26，跨度 0.14 个百分点——比种子 σ（0.18~0.50）还小。NLL 略有改进（−0.06 nat），但只在 32→64 这一格勉强能看到差别。把上下文从 8 字拉到 64 字，在这桶上**没换来稳定的能力提升**。

**第二，wuxia 上不是单调的。** Top-1 是 10.82 → 9.74 → 11.61 → 11.28：先掉再涨再掉。NLL 的形状类似。曲线有拐点、有平段——和「越长越好」的直觉对不上。

**第三，两个桶都仍然输给 trigram（Top-1），但 NLL 都赢了 trigram。** 这条结论与 Day-2 的按作品切分实验一致：模型在「整体分布准不准」这件事上比 trigram 强，但在「敢押最常见那个字」这件事上不占优。

## 为什么 wuxia 的曲线不是单调

wuxia 句式更自由、长程依赖更多——这是 Day-2 发现六已经知道的定性结论。把它放进 ctx 扫描里，可以看出**长程依赖的存在 ≠ 长程依赖被自动用上**：

- ctx=8 模型也能拿到 10.82%（Top-1），只比 32 差 0.79pt；
- ctx=16 是 wuxia 这次最差的一档（9.74%），且 σ 大（0.92）——也许是优化轨迹里某个不稳定的局部；
- 32 是赢家，但 64 没继续涨——多出来的位置信息没变成更好的预测。

可能的解释（都没做对照实验）：

- 6.6 万参数的主体相对 20,000 字训练**已经偏少**（见实践篇第 26 篇的参数账），它没有足够的容量把「64 位的远距离关系」学进去；
- 词表内的字搭配比「远距离人物状态」更容易学到，所以模型先学会的是局部；
- 学习率与调度可能不匹配更深的梯度信号。

这三条意味着：**在当前预算下，「更长上下文」不是一个可调的杠杆——要让它真正起作用，得先把数据量和容量都提到位。**

## 边界

- 训练预算只有 20,000 字 × 3 epoch ≈ 200 步。这是个**极度欠拟合**的设置，长上下文的好处在更长训练下可能才会显现；
- 只在 scifi / wuxia 两个桶跑——`story` 短故事的句式模板化最强（Day-2 发现的「trigram 主场」），那里的 ctx 曲线可能更平；
- 我没有做 `heads × ctx` 的交叉（多头注意力是不是能各自抓不同距离的信息，是计划里的下一件事）；
- 评测位置集是「每个位置前置 ≥64 字」，所以这实验测的是「模型能看到 64 字时到底吃进去多少」——它**不能回答**「更长上下文在哪些特定位置能给出决定性帮助」。

**可复现入口**：`py/ablation_ctx.py --mode ctx --bucket scifi`（或 `--bucket wuxia`）；详细设计见 `docs/experiments/2026-09-14-ablation-ctx-mask.md`。
