# loss 越低，故事不一定越好

**系列：从零训练中文小说模型｜第 5 篇**

实验身份：model=MiniLM-char-v1｜corpus=记忆之海(2,668字)｜seed=42(单次)｜steps=400（另含早期 700 步观察）｜protocol=统一协议(eval/protocol.js)

训练语言模型时，最容易产生的冲动是：继续训练，让 loss 变得更低。

但在这个项目里，我观察到过一个不舒服的现象：loss 从 2 左右继续降到 0.53，生成文本反而更像语料碎片的拼接。

早期输出是乱码。
| 步数 | 损失 | 生成状态（提示词「新长安的雨下」） |
|---:|---:|---|
| 1 | 5.873 | 乱码 + 叠字（「块块块」「新新新新」） |
| 100 | 4.429 | 出现标点与短句 |
| 200 | 2.532 | 能连成半句话 |
| 300 | 1.903 | 局部通顺，逻辑仍散 |
| 400 | 1.629 | 成句，但像语料碎片重组 |

这张表的重点不是「越来越好吗」——它当然在变好。问题是**这条曲线不会自己告诉我们什么时候开始变坏**。
训练一段时间后，模型学会了“的”“了”“他说”和中文标点，开始能写出短句。再继续训练，它越来越倾向于把记住的局部片段重新组合，出现“像小说但逻辑不动”的句子，以及“一盏着”这样的缝合。

因此旧版实验台曾经把 0.8～2.5 标成“甜蜜点”。后来我把这个说法降级为“本次实测观察区间”，并移除了自动停止建议。

原因很简单：这个数不是定律。换一份语料、一个模型尺寸、一个 tokenizer 或一套训练步数，loss 的范围都会变化。它最多是一次实验里的观察，不能替代验证集、重复率、训练文本重合度和人类阅读。

现在项目会同时记录：验证 NLL、distinct-2、4-gram 重复率、8-gram 训练集重合率，以及固定提示词下的完整输出。低 loss 只说明模型更擅长预测训练目标，不直接说明故事更好看。

## 不用「甜蜜点」之后，用什么代替

旧版 UI 会建议「就停在 loss 0.8~2.5」。移除之后，项目改成同时记这五项，让读者自己判断：

| 指标 | 方向 | 它替你回答什么 |
|---|---|---|
| 验证集 NLL | 越低越好 | 换到没见过的位置还准不准 |
| distinct-2 | 越高越好 | 用词是否单调 |
| 4-gram 重复率 | 越低越好 | 是不是在自己绕圈复读 |
| 8-gram 训练集重合率 | 越低越好 | 是不是在背原文 |
| 固定提示词完整输出 | 人工读 | 前面四个数都没法替它 |

这五项之间**会互相冲突**。比如 loss 一路下降时，4-gram 重复率往往也降（模型更确定），但 8-gram 重合率会升（更像在搬训练片段）。单看任何一个指标都会得出偏的结论，这也是「甜蜜点」必须被降级成「观察区间」的真正原因。

这也是我认为最值得分享的部分：模型训练不是一条“loss 越低，能力越强”的直线。真正的学习，是找到指标之间什么时候一致，什么时候互相冲突。
