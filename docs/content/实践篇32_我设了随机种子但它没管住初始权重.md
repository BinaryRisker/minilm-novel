# 我设了随机种子，但它没管住模型的初始权重

**系列：从零训练中文小说模型｜第 32 篇（实践篇·实验室周报）**
**前置阅读：原理篇 10（一次训练的账本：epoch、种子、过拟合与 checkpoint）、实践篇 08（三个随机种子就够了吗）**

实验身份：model=MiniLM-char-v1（主体 40,800 + 词表）｜ctx=32｜batch=8｜lr=0.004｜seeds=1234 / 4321｜语料 story 桶前 40,000 字｜30 步｜协议=同参数两次运行逐位对比

「同 seed 同参数跑两次，结果应该一模一样」——这句话我用了半年，直到这次自检把它拆开看。结论是：**在这份代码里它不成立，而且不成立的原因不在随机数生成器，在调用顺序。**

## 缺陷在哪

`py/train.py` 里长这样（修复前的行号）：

```
itos, stoi = build_vocab(text)          # 第 119 行
model = MiniLM(len(itos), cfg)          # 第 120 行 ← 这里就抽了随机数
...
torch.manual_seed(seed)                 # 第 166 行 ← 种子设在这里
```

模型初始化要抽随机数（`normal_(0, 0.02)`）来填 4 万个权重，而种子在这一步**之后**才设。所以：

- `seed` 管住了后面的训练（batch 采样顺序是对的）；
- 但**初始权重来自 torch 的默认 RNG**，那是个按进程、按调用顺序变化的流。

一句话：**这个 seed 是装饰品。**

## 把差异量出来

我写了 `py/verify_seed.py`，同一份语料跑三组对照，逐位比对初始权重与末步权重（`max|Δ|` 是两组 state_dict 的最大绝对差）：

| 组 | 条件 | 初始权重 max&#124;Δ&#124; | 末步权重 max&#124;Δ&#124; | loss 轨迹逐位相同 |
|---|---|---|---|---|
| T1 | 先设种子 → 建模型（修复后） | **0.000e+00** | **0.000e+00** | 是 |
| T2 | 先建模型 → 设种子（修复前） | **1.217e-01** | **2.181e-01** | 否 |
| T3 | 先设种子 → 建模型，但换 seed=4321 | — | 2.178e-01 | 否 |

T1 是「修复生效」的证据：两次运行逐位相同，一个字节都不差。

T2 是失败样本，也是本篇最值得看的一行：**同 seed 跑两次，初始权重的差异是 0.122。**

然后是 T3——换一个完全不同的种子（1234 → 4321）造成的末步差异是 **0.218**，而 T2「同一个种子跑两次」的差异是 **0.218**。两者同量级。

**翻译成人话：在修复前，你换种子和你不换种子，对结果的影响差不多大。** 所谓「复现性」只存在于嘴上。

## 顺手埋的另外两个雷

查这条链的时候还发现两处同类问题，都在同一份「随机性账本」里：

1. **两套随机流。** 训练里 batch 窗口起点走 `random.Random(seed)`（python 标准库），模型初始化与采样走 torch 的全局 RNG。只设一个不等于两条都对齐。这个坑在下一篇（断点续训）里变成了真事故——checkpoint 存的是全局 python RNG 的状态，而真正被消费的是另一个 `Random` 实例，两条流不是同一条。
2. **生成侧根本没设种子。** `py/eval_story.py` 用 `torch.multinomial` 采样解码，一个种子都没设。同一份 checkpoint 两次生成的故事不同 → 故事评测的结论无法复核。

## 修复：一个入口 + 一个顺序

新增 `py/repro.py`，把随机性收敛成两个原语：

```
set_global_seed(seed)      # random / numpy / torch(CPU+GPU) 一次设齐
rng_state() / set_rng_state(s)   # 把两套 RNG 状态打包存取，供 checkpoint 使用
```

并在 `py/train.py` 里把顺序写死：**先 `set_global_seed(seed)`，再建词表与模型**。新增了 `--seed` 之外的 `--manifest` 记录，把「这次训练用哪版切分、多少字」写进 meta，减少「跑完才发现数据不对」的概率。

## 边界

- 只在 CPU、单个 Python 进程内验证。跨机器、跨 torch 版本、多线程 DataLoader 的复现性没测——`torch.use_deterministic_algorithms` 只在 `deterministic_torch=True` 时打开，本项目实验都用的默认关。
- `max|Δ|` 是逐参数张量的最大逐元素差，适合「是否逐位一致」的判定，不适合当训练质量的度量。
- 这次只验了 30 步、4 万字的最小设置。**步数越多，初始权重的差异会被优化过程抹掉一部分**，但「同 seed 两次跑出不同曲线」这件事本身已经足够致命。
- 这篇没测 numpy：训练路径不用 numpy，设种子只是为了绘图/统计脚本也一致。

复现：`python py/verify_seed.py`（默认 story 桶 4 万字 / 30 步）；改规模用 `--chars --steps`
