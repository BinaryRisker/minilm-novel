# 打分机不是作家：解码、采样与温度

**系列：从零训练中文小说模型｜第 9 篇（原理篇）**
**前置阅读：原理篇 1（全景）、原理篇 6（logits 与 softmax）**

实验身份：model=MiniLM-char-v1｜解码=top-k=8, temp=0.5/0.8/1.2, 重复惩罚 1.15｜样本=实践篇第 14/18 篇原文

训练结束，你手里多的是一台**打分机**：每一步给词表里所有字打概率。可概率不会自己变成小说——中间还隔着一层**解码采样**：怎么从这张表里挑出下一个字。同一台打分机，换采样参数就是换文风，所以先立个规矩：**凡是比模型，必须锁死采样参数，否则比的不是模型，是采样器**（实践篇第 14 篇）。

## 四种挑法

| 挑法 | 规则 | 性格 |
|---|---|---|
| 贪婪解码 | 每步都取第 1 名 | 省事，但极易复读——「最安全的话」往往最无聊 |
| 采样（本项目默认） | 按概率抽签，分高的常中、分低的偶尔爆冷 | 有人味，会冒险 |
| top-k=8 | 只在票数前 8 名里抽 | 把长尾乱码拦在门外 |
| 重复惩罚 1.15 | 刚出场过的字压分 | 治小模型的复读机晚期 |

**温度**（temperature）是抽签前的旋钮：先把 logits 除以 T 再过 softmax。T < 1 把差距**拉大**——模型变保守，字字谨慎、爱收句号，但也更快滑向复读；T > 1 把差距**压平**——人人有份，文风放飞，敢用怪字，也容易失控。本项目对比过 0.5 / 0.8 / 1.2 三档：0.5 稳而闷，1.2 活而野。另外一提，常见变体 top-p（按累计概率截断，也叫核采样）本项目**没有实现**，现有代码只有 top-k——将来做字/子词或解码对照时，得先把这一条写进协议。

## 一个必须泼的冷水

采样再精巧，也只是在**模型肚子里挑货**。实践篇第 18 篇放过完整的原文样本：温度 0.5、top-k=8、重复惩罚 1.15，全套常规配置，产出依然是这样：

```text
苏念说，我想了粥。 恒看着一个还的手是什么也没有
```

单句「我想了粥」甚至有点味道，整段读下来人物零决定、事件零发生——**局部流畅 + 全局失焦**。这不是采样器的锅：解码参数全在常规区间。真正的病灶在训练目标里——没有任何一项 loss 问过「人物此刻想要什么」（实践篇第 18 篇的归因，待实验验证）。**温度治文风，治不了不会讲故事。**

## 边界

- 采样参数不改变模型「会什么」，只改变从它肚子里**挑哪句出来**；同一个模型换参数得出不同结论时，先查参数是否一致；
- top-k 的 k、温度 T 都是工作值，没有跑过系统扫描，别当成调优结论；
- 本篇的样本是 5.5 万参数、千字级语料的产物，不能外推到「大模型也这样」。

**在哪里亲眼看**：`index.html` 生成面板的温度滑条拉一圈，同一段提示词各生成三次，自己盲评哪档最像人写的。
