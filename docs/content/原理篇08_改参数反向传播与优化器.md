# 谁在拧那 4 万个旋钮：反向传播与 Adam

**系列：从零训练中文小说模型｜第 8 篇（原理篇）**
**前置阅读：原理篇 1（全景）、原理篇 7（loss 与交叉熵）**

实验身份：model=MiniLM-char-v1｜优化器=Adam lr=0.004 + warmup 15% / cosine / clip 1.0（`py/train.py`）｜gradcheck=eps 1e-5, float64 688/688（实践篇第 13 篇）

loss 喊了一嗓子「错了，罚 1.2」。然后呢？模型里 4 万多个参数（旋钮），每个该怪多少、往哪边拧、拧多少圈——总得有个说法。这套说法就是本篇：**反向传播算责任，优化器拧旋钮，三件套防翻车。**

## 反向传播：一张责任清单

**梯度**（gradient）就是每个参数的责任清单条目：loss 对这个参数的「怪罪程度和方向」。算它是从 loss 出发**倒着**一层层推回去：最后一层错得多明显（原理篇 7 那行 `dlogits = probs − onehot`），前一层的权重该分多少锅，再往前一层又分多少——链式法则，一路分锅分到第一张档案卡。

拿到清单怎么改？**梯度下降**：蒙眼站在山上，脚底摸出哪边是下坡（梯度的反方向），朝那边迈一步。这一步多大，就是**学习率**（learning rate）——本项目的步长是 0.004。步子太大直接滚下山崖（训练发散），太小走到天黑还在半山腰。

## Adam：给每个旋钮配自适应鞋

普通梯度下降穿的是拖鞋——所有旋钮同一步长。**Adam** 每个旋钮发一双智能跑鞋，秘密是随身记两本账：

| 账本 | 记什么 | 管什么 |
|---|---|---|
| m（动量） | 最近一阵坡度的平均**方向** | 惯性：连续下坡就加速，别被噪声带偏 |
| v（二阶矩） | 最近一阵坡度的平均**幅度** | 路况：平坦处迈大步，颠簸处迈碎步 |

所以叫「自适应」：旋钮们各走各的步幅，不再一刀切。注意原理篇 10 会回收一个细节——这两本账占了差不多两倍于权重的内存，而且 checkpoint 忘了存它们（实践篇第 28 篇）。

## 防翻车三件套

本项目的完整配置：`Adam lr=0.004 + warmup 15% / cosine + clip 1.0`。

| 装置 | 干什么 | 防什么 |
|---|---|---|
| warmup（前 15% 行程） | 学习率从 0 爬到 0.004 | 开局责任清单全是噪声，起跑就猛冲必翻 |
| cosine 调度 | 后程沿余弦滑降，越近终点步子越小 | 到了谷底还在大步乱跳 |
| 梯度裁剪 1.0 | 责任清单总长超 1.0 就整体等比缩小 | 某一步被异常梯度带飞 |

## 连「检查器」都要检查

改参数这件事本身也可信吗？实践篇第 13 篇翻过一次车：用「手算数值梯度」对照反向传播——float32 下 800 多个分量「不通过」，眼看要冤枉反向传播写错了；换 float64，**688/688 全过**。真相不是代码错，是 eps=1e-5 的有限差分在 float32 精度下根本算不准。教训记入项目守则：**测试失败先怀疑精度，再怀疑实现。**

## 边界

- lr=0.004 是**工作值**，不是最优值——本项目没做过学习率扫描（batch/学习率配对实验在计划清单上，未跑）；
- 反向传播只保证「这一步往下坡走」，不保证山下没有沼泽（过拟合，原理篇 10 见）。
