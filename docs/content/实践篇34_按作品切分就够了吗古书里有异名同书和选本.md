# 按作品切分就够了吗？古书里有「异名同书」和「选本」

**系列：从零训练中文小说模型｜第 34 篇（实践篇·实验室周报）**
**前置阅读：原理篇 11（评测与基线：留出集、Top-1、NLL 与 trigram）、实践篇 24（我的评测在替基线作弊）、实践篇 33（续训后 loss 更低不代表续训是对的）**

实验身份：buckets=gudian / wuxia / urban｜语料=按作品整篇切分（train 出词表）｜协议=① 40 字片段逐段精确查找 ② 内容锚点（winnowing）两两比对 ③ 同模型跨测试集的逐作品指标对照

前一轮我把「留出集」修成了**按作品切分**：一部作品整篇进 train 或整篇进 test，不再出现「同一部作品的头进 train、尾进 test」（Day-2 的口径来源与受控 A/B 见 `docs/experiments/2026-09-14-worksplit-nll-converge.md`）。这件事做完之后，我以为隔离就干净了。

审计脚本第一遍跑出来的结果，打了我的脸：

| 桶 | val 的 40 字片段能在 train 里找到 | test 的 40 字片段能在 train 里找到 |
|---|---|---|
| gudian（古典） | **18/150（12.00%）** | **22/150（14.67%）** |
| wuxia（武侠） | 0/150 | 0/150 |
| urban（都市） | 0/150 | 0/150 |

gudian 的留出集里，**每 7 个片段就有 1 个能在训练集里逐字找到**。作品 id 不同、内容哈希不同、标题不同——但正文是重合的。

## 泄漏长什么样

我顺着命中的片段反查，找到了源头，一共三类，全是同一个母题：**同一份正文，以不同身份出现在两部作品里**。

| 留出作品 | 训练作品 | 内容锚点重合 | 精确复核 | 性质 |
|---|---|---|---|---|
| 《新齐谐》 | 《子不语》 | 0.572 | 0.421 | **异名同书**（《子不语》又名《新齐谐》） |
| 《三国演义》 | 《三国志演义》 | 0.552 | 0.369 | **同书异本**（不同版本/校订本） |
| 《警世通言》 | 《今古奇观》 | 0.135 | 0.058 | **选本重复**（《今古奇观》是三言二拍的选本） |
| 《醒世恒言》 | 《今古奇观》 | 0.094 | 0.041 | 同上 |
| 《西湖二集》 | 《今古奇观》 | 0.067 | 0.044 | 同上 |
| 《喻世明言》 | 《今古奇观》 | 0.067 | 0.022 | 同上 |

而且这些不是零散的对，它们连成了簇：《今古奇观》把「三言二拍」里的四个作品串成一个 **7 部作品的同源簇**。按作品切分对这类结构完全无能为力——**它切的是「作品」这个行政单位，泄漏却是「文本」这个物理事实。**

## 修：内容锚点 + 并查集合并

新增 `py/dedup_works.py`：

1. 每部作品取一批**内容决定的锚点**（winnowing：k=20 的字符片段，在宽度 20 的滑动窗口里只保留哈希最小的那个）。锚点只由内容决定，所以同一段文字在任何文本里产生同一批锚点——**与对齐无关**；
2. 两两算包含度（A 的锚点多大概率也出现在 B 里），双向取最大（选本是单向包含，取最大才抓得住）；
3. 并查集合并成簇，**一个簇整体落在同一个 split**：簇里有 train 作品就整簇进 train，绝不把「训练集见过的文本」留在留出集里；
4. 产出一份新清单 `data/manifest_v2.jsonl`（原文件不动，旧实验可复现）。

结果：gudian 移动 4 部作品，切分从 44/5/6 变成 **48/4/3**。再跑同一份审计：

```
桶 gudian: val 0/150 (0.00%)   test 0/150 (0.00%)   ← 修复前 18/150、22/150
判定：通过（按作品切分的 val/test 与 train 无作品级/文本级重合）
```

## 失败样本：修了，指标几乎没变

这是本篇最该看的部分。我用同一个模型（同一份训练数据、同一个 seed）在**逐部作品**上评测，把留出集分成两组：「同源兄弟在训练集里」的 4 部（被污染）与 7 部干净的：

| 组 | 作品 | 平均 Top-1 | 平均 NLL |
|---|---|---|---|
| 被污染 | 三国演义、二刻拍案惊奇、警世通言、新齐谐 | 10.02% | 6.750 |
| 干净 | 封神演义、镜花缘、搜神记、神仙传、无声戏、斩鬼传、蛮书 | 9.73% | 6.826 |
| 差值 | | **+0.29pt** | −0.076 |

三种子（1234/42/2024）的差值：Top-1 **+0.29 / +0.52 / +0.18**（均值 +0.33 ± 0.14），NLL 三个种子都是 −0.08 量级（均值 −0.082 ± 0.005）。

**方向一致（污染组确实虚高），但量级很小。** 对比一下同一批作品的 Top-1 分布是 8.16% ~ 12.39%——作品之间的天然差异（4.2pt）比泄漏效应（0.33pt）大一个数量级。

诚实的结论是：**「修完泄漏指标没怎么变」不是修复无效的证据，而是修复的效应在本文这个规模（6.6 万参数、10 万字训练）下本来就小。** 但我依然必须修它——因为我看不出有什么理由保证：模型变大、训练变长、语料换成更同源的选本集合之后，这个偏差还会是 0.3pt。

## 顺手记两个我自己踩的坑

1. **「两边各自抽样求集合交集」是错的方法。** 同一段文字在两部作品里的起始位置对不齐，交集被稀释约 1/stride：实测《三国演义》与《三国志演义》的真实重合是 38%，用 stride=10 的集合交集只算出 **3.8%**，直接低于阈值、漏检。第一版脚本就是这样报出「同源对 0 组」的。
2. **改用「对另一部全文精确查找」是对的但不实用**：每对 ~1.25s，gudian 的 1485 对要半小时。最后用 winnowing 锚点（对齐无关、O(n)、crc32 可跨进程复现）才同时满足准确与便宜——22 秒跑完三个桶。

另外，旧口径（`corpus.json` 的连续 90/10）也一并量了：gudian 有 1 部作品（剪灯新话）同时横跨两段；test 段只包含 4 部**按字数排在最尾（也就是最短）**的作品；拼接只保留 200 万字，**丢掉了全池 81.9% 的正文**（wuxia 63.7%、urban 52.8%）。这条老路的问题比泄漏更多一层：它连数据都是缺的。

## 边界

- 阈值 0.05 是拍的（较短作品有 5% 的 40 字片段逐字相同即判同源）。调到 0.02 会并出更大的簇，调到 0.2 只剩异名同书那一类。**这份阈值表我没做敏感性分析**，只在 0.05 上报告了结果。
- 只查了 gudian / wuxia / urban 三个桶。story / scifi / xiandai / localugc 没查（前者是现代短篇，后者是同一批生成式文本，**很可能有大量近重复**，值得单独一轮）。
- 修完 gudian 的 test 只剩 3 部作品，留出集更小、方差更大；跨档位比较时要记住这件事。
- winnowing 是**估计**：候选对都做了全文精确复核（表中「精确复核」列），但「没有候选对」的作品之间没有做精确复核，理论上存在漏检。
- 所有数字锚定在 manifest 快照指纹 `4bafc1993955d29c`（32,036 部）。跑本文时数据管线正被另一条工作流持续重写，我另存了快照以免数字漂移——**复现时请用快照**，不要用实时文件。
