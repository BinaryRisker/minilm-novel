# 从随机初始化到可验收小说模型：设计 V3

日期：2026-09-14。状态：待实施设计，不代表已训练出新模型或通过人评。

配套：[TODO](TODO_NOVEL_MODEL_LEARNING_V3.md)、[研究核查](research/NOVEL_SCRATCH_RESEARCH_20260914.md)、[人工验收协议](NOVEL_HUMAN_EVAL_V1.md)。V2 的代码审计及 P0 修复仍有效；涉及正式版本采用外部基座的选项由本版覆盖。

## 1. 目标与硬约束

交付一个可下载、可离线加载的自训练模型，附带自建 tokenizer、训练配置、数据身份、断点恢复、完整小说生成程序、全量测试输出和人评记录。所有模型参数从随机初始化开始；后续 SFT 或偏好训练只能从本项目可追溯检查点继续。不得加载外部预训练参数、嵌入、LoRA 或合并权重。

tokenizer 仅在本项目训练集上拟合。允许借用标准 Transformer 实现与训练库。外部模型只用于方法比较或单列的评测基线；如以后使用外部模型生成文本/标注，必须显式记录来源、费用、比例和许可，不能声称数据完全人工原创。本轮不调用付费生成服务。

正式自主生成链路的规划、正文、摘要和修订均使用自己的模型；规则程序可负责状态存储、校验、重试和导出。不得用强外部模型完成关键写作步骤后把系统成绩归于自训练模型。

首个完整交付目标：两类受限中文短篇（日常故事、轻悬疑），6000–10000 个非空白中文文本字符、6–10 个场景、3–5 个主要人物，有开端、发展和结局。该规模是产品目标，不是现有能力。十万字长篇列为后续扩展，不能用循环追加文字代替达标。

## 2. 当前基础与优先问题

当前 JS/PyTorch 数学对齐和教学实验有价值，但约 0.3M 级模型、短上下文、下一字排名不能证明小说能力。[V2 审计](PRD_NOVEL_MODEL_LEARNING_V2.md) 已发现：初始化种子位置错误、resume 不续训、test 被重复调参、故事评测重复计算 prompt、事实检查只看名字、数据与缓存身份不完整。必须先修复这些问题，才允许用新分数支撑规模选择。

保留手写数学路径作为教学与回归基准。新增 `py/novellm/` 作为可训练路径，不静默替换历史实验含义。现有约 5511 万字符在分词后重新计量；字符数、唯一 token、重复曝光 token 分别记录。

## 3. 硬件与规模决策

用户设备：报告为 4090 GPU、8GB 显存、32GB 内存；另有 Mac mini M4 16GB，可接受租 GPU。先按 8GB 可用显存设计，型号与容量由 doctor 实测确认。M4 作为第二平台的推理、数据和微型训练验证；不把两台机器内存合并计入预算。租用预算尚未指定，先生成资源估算，不启动租用。

候选架构统一为无偏置因果 decoder、RoPE、RMSNorm、SwiGLU、绑定输入输出嵌入，普通多头注意力；先减少同时变化的因素。

| 候选 | d / 层数 / 注意力头 / FFN / 词表 | 精确参数量* | 决策 |
|---|---|---:|---|
| A | 512 / 8 / 8 / 1408 / 8192 | 29,893,120 | 本地首选规模候选，先短上下文试跑 |
| B | 768 / 12 / 12 / 2048 / 16384 | 97,536,768 | A 的数据与预算消融完成后考虑 |
| C | 1024 / 24 / 16 / 2816 / 16384 | 325,108,736 | 数据不足时不扩；需本机内存实测或租卡估算 |

*按 `V*d + L*(4*d*d + 3*d*ff + 2*d) + d` 计算，要求实现与上述结构完全一致；上线前由代码断言核对。这些不是质量保证或显存承诺。

上下文从 512/1024 起步，再试 2048/4096；每阶段用中文 token/字符分布确定能容纳多少正文。8GB 上采用 microbatch 1、梯度累计、经过验证的混合精度、激活检查点，先实测再启用。禁止依赖量化预训练模型来规避随机初始化要求。

每个设备先运行微型闭环，再对 A 的 1024/2048 上下文测预热后至少 200 个训练步：有效训练 token/s、峰值显存/RSS、loss、数值稳定性、恢复开销。训练时间估算为目标曝光 token ÷ 实测 token/s，再单列评测、存盘与数据生成开销。内存估计必须含优化器、梯度和激活，不能只报权重文件大小。

预算实验先比较 A 的 0.1B、0.3B 曝光 token 检查点；只有验证集与完整故事质量仍改善，才考虑 1B。B/C 的预算依据 A 的学习曲线和新增有效数据另定。重复轮数必须披露；不能将反复读取现有语料称作新增数据。各比较组固定数据混合、目标集合，记录计算量，区分同 token 与同计算预算比较。

## 4. 数据与训练课程

数据单位是完整作品及其派生家族。`story_id/group_id/source/license/purpose/text_hash/split_version` 必填；近重复、改写、译本、同作品章节同组切分。既有反复使用的 test 降为开发参考；锁定新的测试家族与人工测试题，禁止参与分词、模板生成和调参。

优先建立现代中文受限故事集：用人类可审阅的词汇范围、人物数、冲突类型、结局类型控制难度，并交叉组合，避免所有故事只有同一套句式。先人工审查小批完整样本，再决定扩量；现有古典/网文材料分别计量，不默认能覆盖现代短篇。

训练课程：

1. **语言与完整短故事**：从 step 0 随机初始化，学习 300–800 字有结尾的故事。逐步混入更长的人类正文，保留文档边界和 EOS。
2. **层级条件任务**：从人类正文反向构建主题、人物、大纲、场景和状态标签，保留证据位置及标注来源。训练“题目→计划”“计划+已发生状态→场景”“正文→状态摘要”等任务。写正文时屏蔽条件部分 loss；规划任务的计划本身是目标，不能一并屏蔽。
3. **生成历史适应**：加入自模型生成的历史、错误状态与有证据的修订样本，减轻只在完美历史下训练的问题。保留失败样本，不能把自生成文本直接全部当优质真值。
4. **多场景完整短篇**：在自己的检查点上扩上下文及目标长度；同时保留短故事质量。人工偏好优化只在稳定 SFT 与可靠人评之后另立实验，不以 RL 作为首个修复方案。

反向抽取的计划只用于训练或明确标注的上限实验；真实测试由题目自行规划，不能把参考答案的完整事件作为输入却声称自主构思。

## 5. 运行架构与状态

`数据版本 → 自建 tokenizer → 随机初始化预训练 → 自检查点多任务训练 → 导出 → 题目/种子 → 自模型规划 → 场景生成 → 校验/有限修订 → 全文与证据报告`

`py/novellm/` 拆分 model、tokenizer、dataset、trainer、checkpoint、generate、planner、state、pipeline、evaluate、doctor。先提供 CLI 和 JSONL 进度，保留未来 HTTP/UI 接入点；本阶段不新增服务、账号或任务中心。

检查点保存模型、优化器、学习率调度、各 RNG、数据游标、累计 token、代码/数据/tokenizer/config 身份和父检查点。`init=random` 的根节点记录初始化种子及 step0 哈希；后续每次恢复校验父链。只导入权重必须叫 warm_start，不能伪装精确续训。

生成记录包括 `run_id/checkpoint_id/input/seed/effective_context/continuation/stop_reason/attempts/tokens/elapsed`。正文与 prompt 分离。每场景在候选区生成，校验后原子提交；中断后续跑不重复提交。失败、取消、超预算均有显式终态，最大重试 2 次，原始候选全部保留。

状态包括世界事实、人物认知、叙述者说法、读者已知信息、计划事件、实际事件、伏笔与回收。每项带场景/正文证据、置信状态、版本；摘要不能凭空提升为事实。隐瞒、误解和不可靠叙述不能简单判作矛盾。状态提取失败时保留原文及待核验项，不静默覆盖已确认事实。

发布产物：模型与 tokenizer、最小推理依赖锁、配置与许可清单、全书 txt/md、逐场景日志、运行清单、自动报告、人工评审导入模板。干净环境离线加载必须能完成一部短篇；训练依赖与推理依赖分开。

## 6. 用户流程、文章与界面

用户先检测设备、构建合法数据版本、运行微型随机初始化闭环，再选择已测预算训练；加载自己的导出模型，输入题目和种子，生成全文及检查报告，最后导出匿名评审包。长任务支持 Ctrl+C 安全存盘和带身份校验的恢复，显示阶段、已训练 token、耗时和估算剩余量。

本阶段以 CLI 为主，现有离线页面保持教学用途。若后续接入生成页面，必须显示运行状态、取消/恢复和失败原因，移动端验证 375px 宽布局、长正文换行与下载；训练不在手机浏览器执行。API/SSE 和数据库变更不属于本轮必要工作。

每个里程碑同步产出一篇研究文章：问题→假设→数据/代码身份→命令与预算→完整结果→失败案例→结论边界。保留原始产物，文章中的数字链接 run manifest；自动摘要是草稿，发布前核对。先修订 V2 指出的实践篇 24/31 归因和命令错误，再分享新结论。

建议文章序列：①旧评测为何不足；②从零中文小故事数据；③8GB 显存的真实训练预算；④模型自己学会规划；⑤状态与修订是否有用；⑥完整短篇盲评及失败样本。标题不能提前写成“已达到人类水平”。

## 7. 验收、风险与阶段退出

- G0 工程：同 seed 初始化一致、恢复等价、数据隔离、空输出不获分；CPU 微型训练到离线导出全链路成功。
- G1 短故事：30 个开发题全量导出；至少 24 个经人工确认包含可理解的发展与结尾。未达标先诊断数据/语言能力，不进入长篇包装。
- G2 自主场景链：自己的模型完成规划和 3 个相连场景；验证原文证据、状态提交和中断恢复。报告 direct 与 pipeline 两种结果，避免系统掩盖模型能力。
- G3 正式短篇：按独立[人工协议](NOVEL_HUMAN_EVAL_V1.md)完成 20 题锁定测试与功能可靠性验证。自动分数通过但没有真人记录时，状态必须是“待人评”。

上述比例是拟定产品门槛，不是文献公认标准。低成本小模型可能长期不能满足 G3：先缩小题材与字数、补有效数据，再看验证曲线是否支持扩参数；不得修改锁定集来制造通过。外部模型可作差距参考，但其结果不能补交自模型失败项。

## 8. 回滚与边界

新路径用显式入口启用，旧模型、文章与结果只追加勘误或版本索引。出现数值回归，退回最近通过验证的检查点和配置；数据污染则作废相关结果并新建版本，不能只删除坏样本继续沿用得分。暂不做分布式训练平台、多人协作写作、商业发布或超长上下文创新；优先证明完整作品可生成且可被人检验。
