## 1. 判断与实际进展

V3 方向仍成立，执行质量需要修正。“P0 出口全部达成”与实际契约不符，应改为“基本路径通过，数据身份、缓存、测试隔离和恢复契约待收口”。可以继续 P1 的模型开发和设备小试，但不能开始据此得出质量结论的大规模训练。

已看到真实进展：初始化前设 seed；检查点新增优化器与 RNG；生成只返回 continuation；默认提示词可追溯；split 指纹、锁定集工具、许可分类和 doctor 已实现。现有 58 项 unittest 全部通过；数学对齐 forward 2/2、raw grad 20/20、clip 20/20、Adam 20/20 通过。

`py/novellm/` 目前只有 `doctor.py` 和包初始化。30M 新架构、自建分词训练、故事课程、多场景自主生成、离线导出与真人验收仍未实现。这不属于本轮新发现的回归，但限制了能宣称的完成度。

## 2. 必须优先修复的问题

### F1 [P1] 恢复默认参数改变真实训练，元数据却仍记录旧配置

位置：`py/train.py:145`、`:267`、`:279`、`:286`。载入旧 meta 后，batch/lr 仍取 argparse 默认值，未显式填写时也不会继承检查点。合成反例：初始 batch=2、lr=0.002；只传 resume 和目标步数，实际变成 batch=8、lr=0.004，meta 仍是 2/0.002；与连续训练权重最大差约 0.002488。

另在 `:162` 修改 chars 只告警继续：探针从 100 改 200，训练实际使用 200，meta.chars 仍为 100。这会误导重建数据、新颖度参照和预算统计。不是“抽 checkpoint 模块”的形式问题。

修复：恢复参数采用未指定标记，默认继承；exact resume 拒绝数据、调度与训练参数漂移；有意改变配置使用显式 fork/warm_start，新 run_id 与父检查点，更新有效配置。中间检查点必须包含完整身份。保存使用临时文件+原子替换，保留上个可恢复版本；当前 `save_checkpoint` 直接覆盖还不能承受写盘中断。

### F2 [P1] 数据校验没有覆盖实际正文、家族和使用范围

位置：`py/splits.py:134`、`:214`、`:229`。verify 只检查清单中精确重复与清单/报告指纹；读正文没有校验正文哈希。反例使用生产验证分支，清单不变而正文被修改仍成功返回；同 parent_id/dedup_cluster 跨 train/test 且内容不同也能通过。

这不证明现有全库已经污染，而是证明入口无法阻止污染。修复需实际数据分片哈希、家族跨 split 不变量、用途策略和审计版本；验证后固定数据快照，不让默认清单自动切换改变恢复内容。大量文件应一次验证并生成不可变分片清单，避免每个 batch 重哈希。

`run_identity.py:95` 不含 bucket、chars、tokenizer、代码/协议与数据顺序，反例不同桶和不同切片产生相同身份。`:67` 用首行是否带 dedup_cluster 判断全库近重复状态，不能证明审计覆盖率。`train.py:324` 又只在 args.bucket 存在且训练结束后 attach，通常 resume 不重传 bucket，中间快照也可能缺身份。应在开训前解析一次完整 effective manifest，并在所有快照引用同一身份。

### F3 [P1] sweep 仍信任文件名缓存

位置：`py/sweep_worksplit.py:268`、`:485`。trigram 缓存只要 JSON 能解析就返回；模型结果只要同名存在就加入汇总。探针将缓存写为 `{"stale":true}`，仍被接受。新结果也没有接入 run_identity。

修复：统一数据/配置/协议签名和 schema，命中前严格比较；report_only 同样拒绝混合协议。旧数据只进入显式历史报表，不与新结果合并。原子缓存文件还需每进程独立临时名称，避免并发共享 `.tmp`。

### F4 [P1] 每个候选评一次 test，不等于整个研究只验收一次

位置：`py/sweep_worksplit.py:247`、`:500`、`py/locked_test.py:61`、`py/eval_story.py:60`。sweep 每个 size/seed 都输出 test；默认故事评测也从 test 取前缀。训练、sweep、故事评测均未接入 locked_test 校验/使用控制。冻结工具从原有 test 中抽样，未排除历史已经看过的作品；重新冻结也不会抹去历史曝光。

修复：开发入口默认只读 train/dev；选择配置后由独立 final_eval 加载不可变选中清单、锁定集与评测协议。允许复算同一已声明实验用于复现，但使用台账记录每次访问，禁止把复算或多候选比较称作新盲测。新盲测题组应有未曝光来源证明。锁定漂移保留旧版本，不覆盖后再称首次验收。

### F5 [P1] val 曲线叠加了 test 的 trigram 水平线

位置：`py/sweep_worksplit.py:472`、`:739`、`:743`。模型 curve 已改 val，但 trigram 仍用 test_ids，图纵轴标“val 集 NLL”。由此判断模型何时超过 trigram 不成立。应分别保存 baseline_val/baseline_test，并在画图及汇总断言 split、目标位置哈希相同；旧协议混入也应拒绝。

### F6 [P1] 当前 GPU 验证路径有明确设备不一致

位置：`py/train.py:297` → `quick_eval` → `py/minilm_torch.py:eval_ids`。训练模型可在 CUDA，eval_ids 内部创建 CPU tensor；首次 val 时会产生设备冲突。这是代码路径推导，本机无 CUDA，未实际复现 CUDA 报错。

另 `torch.load(map_location=device)` 将 CPU RNG tensor 一并映射到目标设备，恢复函数遇错只告警重设 seed，不能算精确恢复。应 CPU 加载状态，模型/optimizer 明确迁移，各后端 RNG 单独恢复；MPS RNG 尚未覆盖。加入目标设备上的训练→val→save→resume→生成微型端到端测试。

### F7 [P2] doctor “只读、绝不猜”与实现不符

位置：`py/novellm/doctor.py` 中 `_precision_probe`、`physical_cores`。探针确认 torch.randn 消费全局 RNG；物理核数直接写 logical//2，属于猜测。8×8 matmul 成功只能说明该操作可执行，不说明完整低精度训练可用，更不说明速度收益；TF32 开关状态也不是硬件能力探测。

修复：常量张量或隔离 RNG；物理核用系统接口/psutil，缺失为 null；字段区分 op_supported、backward_verified、training_verified、measured_throughput。现有测试只比较输出布尔值，没有检查全局 RNG。

### 其他需纳入实施的缺口

- UNK 仍作为停止符；关键词命中仍忽略事实属性；默认自动题 facts/events 为空。因此当前脚本仅能作续写统计，不能作事实一致性验收。
- eval_story 重建当前默认训练语料，而非检查点冻结快照；novelty4 仅对前 40 万字建索引，应披露覆盖范围，不能当全训练集抄录检测。
- `minilm_torch.py` 新增 causal=False 消融开关：实验路径有意义，但正式训练/评测入口应拒绝非因果配置，防止 teacher-forcing 看未来答案后得到虚高分数。
- 200 个 40 字片段零命中仅表示该探针未检出，不是近重复清零证明。应保存样本覆盖、按作品分层抽查及漏检评估；不要把一次抽样全绿写成全库无泄漏。
- TODO 中锁定指纹与磁盘内容已不同；文章勘误仍未收口。状态表应链接实际 run manifest，避免手填历史数字自动沿用。

## 3. 主流路线与新研究对本项目的含义

核查截至 2026-09-16，以下是代表性路线，不是市场占有率统计。外部方案多依赖成熟预训练模型，不能把系统能力直接迁移为 30M 随机初始化模型的能力承诺。

| 路线 / 一手来源 | 可借鉴与尚未解决的问题 |
|---|---|
| [AI_NovelGenerator](https://github.com/YILING0013/AI_NovelGenerator) | 已公开设定、章节、人物/伏笔状态、向量检索和校对流程，依赖外部/本地模型接口。适合借工作流；README 功能描述不是独立文学质量证据 |
| [StoryWriter](https://arxiv.org/abs/2506.16445) | 事件大纲→章节规划→动态压缩历史。摘要会丢细节，自生成历史会传播错误；本项目要有原文证据与阶段消融 |
| [PageStorm](https://arxiv.org/html/2605.17064v2) | 长目标与层级脚手架训练，保留人类正文监督；基座与算力远大于本项目。长输出和首章指标不能替代整篇人评 |
| [SimpleStories](https://arxiv.org/abs/2504.09184) | 用参数化任务控制合成故事多样性，适合小模型课程。必须验证中文、目标题材和组合泛化，不能只增加近似模板 |
| [ConStory-Bench](https://arxiv.org/abs/2603.05890)，2026-03 | 2000 题、5 类 19 子类，判定带正文证据；研究报告事实/时间错误突出、常在叙事中段。应加入按章节位置的错误分布，自动 checker 仍需人校准 |
| [StoryAlign](https://arxiv.org/abs/2605.04831)，2026-05 | 1133 条人工核验偏好实例，研究指出通用奖励模型不善于选出人偏爱的故事。先校准评审/奖励，再谈 BoN 或偏好优化，不能自己打高分即验收 |
| [SAGE](https://arxiv.org/abs/2609.06611)，2026-09-06 | 最新预印本区分可观察规则与文学解释维度；100 篇故事、600 次评估的研究范围有限。可补充情感层次、主题等访谈问题；模型评审一致不等于真人效度，不据此宣称理论上限 |

数据预算方面，[Scaling Data-Constrained Language Models](https://www.jmlr.org/papers/v26/24-1000.html) 研究有限数据下的重复训练；[Mixture Pretraining Under Data Constraints](https://arxiv.org/abs/2605.12715) 在 2000 多次训练中研究目标数据比例与重复的关系。后者 arXiv 是 2026 年 5 月，Apple 页面列为 8 月，不能把网页发布日期当成新论文版本。其部分条件下的 15–20 次重复不是本项目推荐 epoch。

[Internal Data Repetition](https://arxiv.org/abs/2606.24998) 则研究部分文档不均匀重复造成的计算损失。两类结果不能简化为“重复总是好”或“重复总是坏”：要区分全语料多轮、优质目标域重采样、无意的局部重复。它们支持把作品曝光分布与配比纳入实验，而不是只看去重后总字符。

## 4. V3.1 设计增量

### A. 模型与数据规模实验更可解释

保留约 30M 候选作为第一条可用训练线。先在固定词表/数据上用微型配置验证工程，再比较同族 10M 与 30M；词表大小独立消融，避免 V3 的 30M/100M 同时改变词表导致无法归因。跨词表比较 NLL 时增加 bits/byte 或统一字符归一指标，不直接比较每 token perplexity。

正式语料先冻结可用于目标发布用途的子集，不在全部数据训练完后才发现导出策略不允许。这里是项目数据契约，许可分类器不替代来源事实审核。统计目标域/通用中文/合成文本占比、每作品曝光、近重复簇、长度与题材分布。

初步配比实验：目标完整故事占 25% / 50% / 75%，其余为同用途的通用中文；固定 token 预算和样本池，先短试筛掉明显差组，再复核候选。该比例是实验设计而非文献结论。按分域 val、完整故事人评和复制率选择，不预定“数据越多越好”。

### B. 先证明任务可学，再增加代理角色

使用同一个自训练模型承担不同任务，不先搭多模型平台。设两个诊断上限：给正确短计划时是否能写好场景；给正确状态时是否能保持一致。上限测试单列，正式成绩仍从题目自主规划。若正确计划都写不好，先补正文能力；若上限好而自主差，才增加规划训练。

上下文预算按 tokenizer 的 P95 长度分配：固定设定、当前场景计划、相关状态、最近原文、输出预留。超限时可解释裁剪并记日志。检索优先实体 ID、时间、事件依赖和词法匹配，不强制引入外部预训练 embedding，保持离线自主目标。

### C. 状态更新采用有证据的事务，修订必须计算净收益

正文生成后先提议 state_delta，再验证引文、时间与实体；通过后正文与状态一起提交。计划事件不能当既成事实。无法判定时标 unknown 并保留原文，不能捏造一致性。

新增指标：伏笔提出/到期/回收、角色目标进展、每章节重大矛盾、失败章节位置、修订修复数和新增错误数。保留原稿；只做局部修订，修订无净改善则停止。固定最多 2 次是成本边界，不是保证质量。

### D. 人评提前，长度逐级扩大

将小规模真人阅读移到数据样本、300–800 字完整故事、3 场景三个阶段；保留最终 6000–10000 字盲评。完整生成与人类续写分开测。对开篇、中段、结局分别记录质量，避免首章好看遮盖后段崩溃。

直接生成、加计划、加状态、加修订在相同总生成预算下比较，并另报不限制预算的质量/成本曲线。自动约束满足、独立人类偏好、实际编辑分钟数分开；自评得分不作唯一训练奖励。正式测试题按题目聚类统计，不把多评审当独立故事。

## 5. 交付、工作流与验收

用户流程保持 V3：设备检测→小试→预算训练→导出→自主全文→盲评包。本轮不新增 Web/API/数据库。CLI 长任务需要 cancel/resume、原子产物及显式终态；未来移动端继续按 V3 的窄屏、长正文、下载和状态一致性验收，本轮没有浏览器改动或验收。

新功能仍使用独立入口，保留 JS 教学与旧实验。出现回归回到已验证配置/检查点，历史结果标注协议不覆盖。文章优先写“为什么 58 项测试通过仍漏掉恢复错误”“混合数据与重复曝光”“规划/状态在同预算下是否有效”；每篇附失败例和命令身份。

本轮范围：58 项单测、62 项数学对齐、合成反例、代码路径审查与一手资料核查。未重跑全量近重复扫描、长预算训练、真实 CUDA/MPS、浏览器、完整小说或人类评审。当前执行机 torch 2.14.0+cpu，无 CUDA/MPS，不能据此估算用户 GPU 的吞吐。
